# 通用编码底线

适用于全部代码（后端、前端、工具脚本）。与 `AGENTS.md` 的「禁止项」配套，本文件讲判断标准。

## 变更范围

- 变更 **MUST** 最小、完整、可验证，且限于当前任务。
- **MUST NOT** 为假设的未来需求预建抽象、接口、事件、扩展点。新增设计 **MUST** 同时有当前需求与当前消费者。
- **NEVER** 使用空实现、恒定结果、log-only、吞异常、伪成功或静默失败。
- 现有实现与本文件冲突时 **MUST** 修正实现，**MUST NOT** 复制或扩大错误模式。

## 共享代码

- 共享代码 **MUST** 业务中立、有明确所有者，且至少有两个真实消费者。
- 共享代码 **MUST NOT** 包含业务状态、业务规则、跨模块业务 DTO、Repository、持久化模型。
- 每个事实、常量、规则 **MUST** 有唯一权威所有者。出现第二处定义时 **MUST** 合并，**MUST NOT** 靠注释说明两者「保持一致」。

## 持久化与副作用

- 单条及批量 `INSERT`、`UPDATE` **MUST** 以「执行无异常 + 事务成功提交」判定成功。
- **MUST NOT** 依据影响行数判断成功或并发冲突——PostgreSQL 的 `ON CONFLICT DO NOTHING`、条件更新命中零行，都是正常结果，不是失败。
- **MUST NOT** 用写后回读替代行数判断。
- `DELETE` 及其他非插入写入 **MUST** 校验实际影响结果。
- 可能被重复提交、重试、重放的入口（导入、回调、定时任务）**MUST** 有幂等策略。
- 事务内 **MUST NOT** 执行外部 IO（HTTP、对象存储、邮件），除非 design 已证明无法拆出并明确超时与恢复。

## 契约与外部依赖

- API、字段、错误、权限语义变化 **MUST** 明确真实消费者与迁移方式。
- 外部依赖 **MUST** 明确超时、错误映射、失败分类与重试边界。
- 外部失败 **MUST NOT** 静默转换为成功。

## 安全与可观测

- 授权 **MUST** 基于已认证主体，对象级权限 **MUST** 校验归属，不得只校验「有权限点」。
- 代码、日志、对外错误 **MUST NOT** 泄漏密钥、令牌、密码与完整敏感数据。
- 关键失败路径 **MUST** 留下足以定位责任边界的最小日志。

## 消息与日志

- 面向调用方的错误信息与生产日志模板 **MUST** 使用中文；错误码、字段名、枚举值、配置键保持原文。
- 日志 **MUST** 表达业务语义，**MUST NOT** 重复消息里已有的信息。
- 自定义异常 **MUST** 只携带处理所需的上下文，**MUST** 保留原始 cause。

## 测试

- 测试 **MUST** 跟随被验证职责，覆盖当前变化与直接回归风险。
- **NEVER** 创建空测试、无断言测试，或为让测试通过而削弱生产约束。
- 测试通过 **MUST NOT** 替代架构边界检查。
