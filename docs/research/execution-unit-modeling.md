# 执行单元建模调研：人、设备与任务池

- 调研时间：2026-10-23
- 来源：公开行业文章与厂商产品页（欧创 WES、巨沃 WES、LogistiVIEW、Reeman Robotics、Cleverence、通天晓、顶妙 WMS 等），未做产品实测
- 结论状态：概念确认，模型为推演，实施细节未验证

## 1. 行业通行说法

多个来源对同一件事的表述高度一致：

| 来源 | 原话要点 |
| --- | --- |
| 欧创 WES | 「人机物协同调度：统一调度人员、AGV/AMR、电子标签、分拣格口，资源冲突自动避让」 |
| 巨沃 WES | 「高度协调自动化设备与人员作业，实现人机混合作业效率最大化」 |
| 某 ERP 任务调度中心 | 「统一的任务池与资源池……将人力资源（拣货员、打包员）与机器资源（AGV、自动分拣线）注册为可调度的**执行单元**」 |
| LogistiVIEW | 「manages labor and automation as a single pool of shared capacity, evaluating capability, location, and readiness」 |
| AI Orchestration 综述 | 「在编排网络里，人类工作者与机器人之间没有本质区别（no fundamental distinction）」 |

结论：**把人和设备放进同一个资源池、用同一套字段描述，是行业主流做法，不是我们的发明。**

## 2. 执行单元需要描述什么

综合各来源，一个可被调度的执行单元至少要能回答五个问题：

| 维度 | 含义 | 人的取值 | 设备的取值 |
| --- | --- | --- | --- |
| **能力** | 能干什么 | 技能标签：冷链、异形件、叉车证、质检 | 载重、取货高度、可搬运具类型 |
| **位置** | 现在在哪 | 当前库区 / 工位 | 坐标 / 当前库区 |
| **就绪状态** | 现在能不能接活 | 空闲、作业中、休息、离线 | 空闲、执行中、充电中、故障 |
| **容量** | 一次能接多少 | 单次任务数（可并行几单） | 载具位数 |
| **可用时间** | 什么时候可用 | 班次 | 电量与充电窗口 |

任务侧同样要有标签：**是否适合自动化、预估耗时、所需载具、优先级**。派工就是「任务标签 × 执行单元能力」的匹配，再叠加就近与负载均衡。

## 3. 人的特殊性：工具是能力的一部分

调研里有一个区分值得注意：

- **AGV / AMR**：自带移动、感知、抓取能力，脱离其他东西也能执行
- **PDA**：本身不能执行任何仓储动作，它只是人的感官与输入输出延伸

所以「人拿 PDA」才构成一个完整执行能力。这一点在实务里有直接证据：

| 证据 | 说明 |
| --- | --- |
| 离线 PDA 方案要求「每位员工分配唯一登录账号」 | 账号是人的，设备是载体 |
| 每条操作记录「时间、设备 ID、任务单号」 | 人和设备同时留痕，责任可追溯到具体那台机器 |
| 设备交接需「重新登录个人账号」 | 换人要换账号，设备可以不变 |
| 设备领用归还要记录责任人与时间 | 设备是有归属的资产，不是公共工具 |

也就是说：**人 + 终端** 是一个逻辑执行单元，但审计上要拆成「人」和「终端」两条线索。

## 4. 交接班怎么处理

这一点决定了模型对不对。行业做法是：

> WMS 用「数字任务工单队列」驱动，作业状态脱离口头交代。上一班未完成的波次在系统中有精确到秒的状态标识，下一班员工登录 PDA 后直接从任务池领取未完成工单。

关键在最后一句：**任务留在池里，不挂在人身上。** 换班只是换执行单元，任务不需要「移交」。

反面做法是把任务绑定到员工 ID 上，交接时要做「转派」，转派漏一条就丢单。

推论：
- 任务的状态属于任务本身，不属于领取它的人
- 执行单元的「当前任务」只是一个缓存指针，可以清空而不影响任务
- 任务表必须能记录「领取人变更历史」，用于追溯跨班责任

## 5. 与资产域的关系

两个概念正交，容易混：

| 概念 | 回答 | 例子 |
| --- | --- | --- |
| **资产（asset）** | 这个东西是谁的、值多少钱、保修到什么时候 | 一台 AGV、一台 PDA、一排货架 |
| **执行单元（executor）** | 谁能接活、现在能不能接 | 一台 AGV、一个人（无论拿不拿 PDA） |

- AGV：**既是资产，又是执行单元**
- PDA：是资产，**本身不是执行单元**，它构成人的能力
- 货架：是资产，不是执行单元

所以不能把两者合成一张表，也不能让资产表承担派工语义。

## 6. 推演出的模型

关键定义：**执行单元不是「人」也不是「设备」，而是「人登录到终端」这场工作会话。** 人没登录终端不能承接作业，终端没人登录只是个设备，两者结合才构成可调度的单元。

```text
executor_session                执行单元（工作会话）
├─ user_id                      人
├─ asset_id                     终端（PDA）
├─ warehouse_id / zone_id       作业范围
├─ capabilities                 jsonb，人的技能 ∩ 终端支持能力
├─ status                       idle | busy | offline | fault
├─ current_task_id              当前任务（可空，仅作指针）
├─ started_at
└─ ended_at                     空表示会话进行中

task
├─ task_type                    拣货 / 上架 / 搬运 / 盘点
├─ required_capabilities        jsonb，派工匹配条件
├─ assigned_executor_id         指向会话，可空，空表示在池中待领
├─ assigned_at
└─ status                       待派 / 已派 / 执行中 / 完成 / 异常
```

四条约束：

1. **一个人同一时刻只能有一个活跃会话**，不能同时登两台终端。
2. **一台终端同一时刻只能有一个活跃会话**，堵住两人共用一个账号不切号的数据失真。
3. **任务不强制绑定执行单元**。`assigned_executor_id` 可空，空即「在池里」。交接班就是结束会话，任务自动回池。
4. **能力是交集不是并集**：人的技能 ∩ 终端支持能力。有冷链资格但拿普通终端，这场会话接不了冷链任务。

审计上，会话 ID 同时指向人和设备，一条扫码日志既能答「谁扫的」也能答「用什么扫的」，追溯与设备利用率用的是同一份数据。

## 6.1 执行单元不是主数据

它由「登录」创建、由「退出」销毁，是运行时记录，不预置、不维护、不导入。因此首期不建这张表——首期没有现场登录行为，建了也没有数据驱动它。

## 6.2 接入形态决定会话的可信度

同样是执行单元，接入方式不同，会话的「真实性」完全不同：

| 形态 | 客户端归属 | 例子 | 会话性质 |
| --- | --- | --- | --- |
| **直连** | 我们自己的 APP 装在设备上 | PDA、工业平板 | **事实**：APP 直接上报状态 |
| **桥接** | 厂商的 RCS / WCS | AGV、堆垛机、输送线 | **镜像**：状态由上游系统告知 |
| **无接入** | 无通信能力 | 货架、月台、充电桩 | 不产生会话 |

推论：

- 桥接会话必须带 `last_sync_at` 与 `integration_mode`，超时未同步标记为 `stale` 而非直接判离线——网络抖动与设备真离线要区分得开。
- 台账上的接入信息按形态不同：直连记 APP 版本与系统版本，桥接记厂商、型号、RCS 地址与协议版本，无接入只记物理规格。
- `integration_mode` 必须可变。将来若自建 WCS，AGV 的对接方从厂商 RCS 换成自有 WCS，若把「AGV = 某厂商系统」写死，切换时台账要重建。

## 7. 会话模型如何覆盖纯设备执行

AGV 不「登录」，它由调度系统唤醒。为了让同一张表覆盖两种形态，会话的两个主体字段都可空：

| 形态 | `user_id` | `asset_id` | 例子 |
| --- | --- | --- | --- |
| 人机作业 | 有 | 有（终端） | 张三登录 PDA-007 |
| 纯设备作业 | 空 | 有（设备本身） | AGV-12 被唤醒执行搬运 |
| 纯人工作业 | 有 | 空 | 纸质单据作业，理论上不需要 |

判定「是不是执行单元」的标准是**是否处于可承接任务的激活状态**，而不是「有没有人」。

## 8. 对 yunWMS 的意义

- 首期无任务、无 PDA、无 AGV，**不建会话表与任务表**。
- 但二期建任务表时，**外键必须是 `assigned_executor_id`（指向会话）**，不能写成员工 ID 或设备 ID。写错这一个字段，接 AGV 时整个派工模块要重写。
- 资产域与执行单元域分开建。AGV 同时出现在两张表里是对的：资产表回答「这台车值多少钱、保修到何时」，会话表回答「这台车此刻能不能接活」。

## 8. 未验证项

- 上述模型由多篇行业文章的表述推演，未对照任何具体产品的数据库设计。
- 「一个人同时接几个任务」在实务中的上限，各来源说法不一，未见统一标准。
- 人机配比（如 1 人 + 1 台 AMR + 0.3 个包装位）是经验值，不适用于本项目推算。
