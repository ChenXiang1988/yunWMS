## 1. R1 需求梳理

### 1.1 功能范围

PDA 端的**交互范式、页面骨架、组件清单、可借鉴的开源实现**。不含具体业务规则（扫码校验、库存口径、单据状态机），那些属于各业务域的 spec。

### 1.2 关键特征（已核实）

**由此推导出的硬约束**：

- 视口只有 320px 宽，**单屏最多两列**，三列宫格会挤到 88px 以下，戴手套点不准。
- 点按区 ≥ 56px（项目已定），比 Android 官方 48dp 基线更严，方向正确：Android 官方明确「触摸界面每个可交互元素的可聚焦区域至少 48dp×48dp，越大越好」（[Android 无障碍指南](https://developer.android.com/guide/topics/ui/accessibility/apps)，页面更新于 2026-10-24）。
- 设备有三通道反馈硬件，但**Web 层只能用声音与振动**（LED 一般由扫描服务/设备侧控制），因此「成功/失败可区分」必须在应用层做。
- 扫描是键盘楔入，**扫描内容走 keydown 事件流**，不是回调；这一点决定了整个输入层设计。

### 1.3 边界与非目标

- 不做原生 App。是否加 WebView 壳见 §3.1、§5.2。
- 不做摄像头扫码（设备有扫描头，摄像头扫码只会带来权限与对焦问题）。
- 不做离线优先架构；本期只要求交互层预留「待同步」状态位。
- 不做 PDA 全业务域页面，不定义各域字段。
- 不重新评估 UI 库（Vant 4 已定）。

### 1.4 现存约束

- Vue 3.5 + Vite 6 + TypeScript 5.7；`apps/pda` 与 `packages/ui-pda` 均未建。
- 令牌三轴已落地，PDA 档位已定（`docs/frontend.md` §2.3）：`control-height-md` 56px、`list-row-height` 72px、`tap-target-min` 56px、`action-bar-height` 64px、`font-size-base` 16px。
- 禁止色值字面量，只允许 `var(--*)`。
- Android 9 的 WebView 版本由厂商固件决定，**不可假设可升级到最新 Chrome**。

## 3. R3 比较

### 3.1 交付形态：纯浏览器 H5 / WebView 壳 / 原生

| 维度 | 纯 H5（浏览器或企业浏览器） | H5 + WebView 壳（Capacitor） | 原生 Android |
| --- | --- | --- | --- |
| 键盘楔入扫码 | 支持（keydown） | 支持 | 支持 |
| 广播模式扫码 | **不支持**（浏览器收不到 Android 广播） | 支持（需厂商插件） | 支持 |
| 厂商 SDK 调参（码制、补光、触发模式） | 不支持，靠设备设置 App | 可桥接 | 全支持 |
| 静默打印 | 不支持（hiprint 需常驻客户端） | 可桥接 | 支持 |
| 唤醒锁 / 常驻后台 | 不可靠（Wake Lock API 在旧 WebView 未必可用） | 支持 | 支持 |
| 更新方式 | 刷新即生效 | 需装 APK，但页面仍可热更 | 需装 APK |
| 体积与内存（2GB） | 最轻 | 多一层壳 | 最重 |
| 开发成本 | 最低 | 中（需 Android 打包与插件维护） | 高，且与 Web 端两套代码 |
| 与既有约定 | 一致（Vant + 令牌） | 一致（同一套页面） | 违背「多端不共享 UI 但共享令牌」的现状，且无人力维护 |

**判断**：一期纯 H5 足够。壳不是「更先进」，而是为了拿浏览器拿不到的四件事：广播扫码、厂商 SDK、静默打印、后台常驻。这四件在一期（商品查询）全都不需要。

### 3.2 扫码输入的四种实现

| 方案 | 原理 | 软键盘 | 同码连扫 | 兼容性 | 结论 |
| --- | --- | --- | --- | --- | --- |
| **A. 全局 keydown 缓冲** | 不渲染常驻输入框，`document` 级监听按键，按时间间隔聚合成一次扫码 | 不弹（无输入框聚焦） | 天然支持（每批独立） | 依赖无 | **主路径** |
| B. 常驻 input + `inputmode="none"` | 输入框保持焦点，靠属性抑制软键盘 | 旧 WebView 可能仍弹出 | 需手动清空值 | Android 9 不可靠 | 仅作 B 计划 |
| C. readonly input + 定时抢焦点 | 反复 `focus()`/`blur()` | 有概率先弹后收 | 需手动清空 | 抖动明显 | **不做** |
| D. 原生广播 | 壳内接收厂商广播后注入 | 不涉及 | 可控 | 需壳 + 厂商适配 | 留到加壳时 |

支撑证据：

- `soft-keyboard-controller` 文档明确写「Some older Android WebViews may ignore `inputmode="none"`」，并建议准备 readonly 或自绘的降级方案。
- 单篇中文实践文章称 `inputmode="none"` 需 Android 10+（**单一来源，未验证**）。DT40 是 Android 9，因此不能把 B 当主路径。
- A 方案不依赖任何 Android 特性，只依赖「扫描内容以按键事件进入页面」这一事实，而设备侧明确支持键盘楔入输出。

### 3.3 组件策略：Vant / Quasar / 自建

| 维度 | Vant 4（现状） | Quasar 2（GreaterWMS-APP 用） | 自建最小集 |
| --- | --- | --- | --- |
| 覆盖度 | 101 个组件，PDA 需要的导航、操作栏、步进器、通知条齐备 | 更全（含布局系统、FAB、对话框栈） | 需自写 8–10 个 |
| 视觉 | 移动端原生观感，与 Ant Design Vue 不冲突但不同源 | Material 观感，与 Web 端割裂更明显 | 完全自控 |
| 包体（2GB 设备） | 按需引入可控 | 整体偏重 | 最小 |
| 与项目约束 | CSS 变量注入，契合令牌四层 | 有自己的 SCSS 变量体系，令牌要二次桥接 | 需自己做无障碍与焦点 |
| 结论 | **沿用** | 落选：重开选型无收益，且要重做令牌桥接 | 落选：只有极少数组件 Vant 没有 |

### 3.4 借鉴对象逐个评估

| 对象 | 值得抄 | 明确不要抄 |
| --- | --- | --- |
| GreaterWMS-APP `ScanAPP.vue` | ① 顶部只读回显框当「扫码结果显示器」；② 中部区域由子路由承载不同作业步骤，**一个扫码入口服务多流程**；③ 所有输入归一到单一 `watch` 管道再分发；④ 每次请求前清空上一轮状态，避免残留 | ① 同码连扫被吞（只清 DOM 不清 `v-model`，值未变则不触发）；② 成功路径无任何应用层反馈，失败与成功的振动时长相同；③ 无 in-flight 锁，高速连扫时旧响应覆盖新响应；④ 用 `165`/`225` 硬编码像素算高度；⑤ 用 `document.getElementById` 绕过数据流，路由切换后空引用；⑥ 监听注册在 `document`、移除在 `window`，泄漏 |
| Microsoft multi-scan | ① 扫描先入**本地缓冲**，提交是唯一一次服务端往返；② 「已扫清单」用左下角列表图标进入，行级可改数量（数字步进器，负数与小数点键禁用）、可删除误扫；③ 主界面实时显示已扫条目数 | ① 不涉及断网、去重与部分失败；② 提交前丢失会话等于丢数据，没有本地持久化 |
| SAP Fiori | ① 扫码按钮必须是**独立按钮，不与输入框捆绑**；② 扫码是主操作且不可用时，降级为手动输入并写明原因（`Scanner not available`）；③ 扫码是次要操作且不可用时，**静默隐藏按钮**，不弹警告 | 其「页眉工具栏放扫码按钮」的布局假设基于顶部工具栏范式，PDA 全屏作业页不适用（物理扫描键才是主入口） |
| 中文一线实践 | ① 一屏只做一个动作；② 头部任务信息 / 中部当前对象 / 底部操作按钮；③ 错误提示靠近字段，不弹一串对话框；④ 严重错误用红色条 + 震动 | 具体数值（字号、按钮大小）缺依据，不引用 |

## 4. R4 结论

### 4.1 交互范式（八条硬规则）

1. **扫码优先**：进入作业页即处于待扫状态，没有「点击开始扫描」这一步；物理扫描键是主入口。
2. **一屏一动作**：一个页面只推进一个状态（扫货位 / 扫商品 / 确认数量），不把后台表单搬上来。
3. **单一输入管道**：键盘楔入、手工录入、后续可能的广播，全部归一为 `scan` 事件；管道内部**串行处理**（队列 + in-flight 锁 + 请求序号），不允许并发覆盖。
4. **同码也必须可见**：每次扫码都刷新「最近扫码」区域的时间与累计次数，即使条码内容与上次相同（这是 GreaterWMS 的现成反例）。
5. **三通道反馈且成功/失败可区分**：成功＝短振动（约 40ms）+ 单声短鸣 + 绿色结果条；失败＝双振动（40-60-40）+ 两声低鸣 + 红色结果条 + 原因文案。**不允许只靠颜色**，也不允许成功与失败用同一振动参数。
6. **本地缓冲 + 单次提交**：批量场景（盘点、批量收货）先入本地清单，提交是唯一服务端往返点；清单入口常驻可见并显示条数；离开页面前若清单非空，必须二次确认。
7. **错误就地显示**：字段级错误贴在该字段下方；单据级错误用顶部常驻条，写明「扫了什么、为什么不行、下一步怎么做」；模态框只用于不可逆操作（放弃清单、删除已提交行）。
8. **单手可达**：主操作固定在底部 64px 操作栏；返回固定在顶部左；**不做右下角浮动按钮**（遮挡内容且与戴手套的拇指落点冲突）。

### 4.4 依赖结论

| 项 | 结论 | 理由与被否原因 |
| --- | --- | --- |
| 扫码输入 | **自行实现** `useScanInput` | 需要可切换的前后缀与最短长度、需与手工输入共用同一管道、需保证不 `stopPropagation` 掉正常键盘事件；`onscan.js` 的启发式参数（`timeBeforeScanTest` 100ms、`avgTimeByChar` 30ms、`minLength` 6）作为实现参考，但有两点不适合直接依赖：默认最小长度 6 会拒掉短码，且其文档自身存在事件名/选项名不一致。**落选**：直接引入 → 参数与副作用都需要改，收益不抵一层依赖 |
| 软键盘控制 | **不引入** `soft-keyboard-controller` | 每周下载 1、单维护者、4 个版本；核心能力是 `inputmode="none"`，旧 WebView 会忽略；自写 10 行等价且有兜底。**落选** |
| WebView 壳 | **暂不引入** Capacitor | 一期无广播、无厂商 SDK、无静默打印需求；引入即多一份 APK 发布与插件维护。触发条件见 §5.2 |
| 原生 UI 库 | **不引入** Material Components / Compose | 与 H5 形态不兼容；列为「若将来改原生」的备选，不进入本期 |
| GreaterWMS-APP | **只读借鉴，不 fork** | Quasar + Cordova 技术栈与项目不符，且扫码页存在重复码丢失、反馈不区分、无请求串行等缺陷；抄交互，不抄实现 |
| 组件库 | **沿用 Vant 4** | 见 §3.3；适配代价见 §4.6 |

`useScanInput` 的行为约定（供实现与测试对齐）：

- 监听 `document` 的 `keydown`，不依赖任何输入框聚焦，因此**不会唤起软键盘**。
- 字符间隔超过 `gap`（默认 50ms，按设备实测调整）即认为上一批结束；整批长度 ≥ `minLength`（默认 4，按业务条码长度定）才作为一次扫码。
- 后缀为 `Enter`/`Tab` 时立即结束当前批；若设备未配后缀，则依赖 `gap` 超时结束。
- 每批结束后**清空缓冲并触发 `scan`**，即使内容与上一批相同（避免 GreaterWMS 的同码丢失）。
- 手工录入走真实 `van-field`，触发时暂停全局监听，避免录入的每个字符被误判为扫码。
- 未挂载/页面隐藏（`visibilitychange`）时暂停监听，避免后台积压。

| --- | --- |
| 控件高度 | `var(--control-height-md)` 56px |
| 清单行高 | `var(--list-row-height)` 72px |
| 操作栏高度 | `var(--action-bar-height)` 64px |

### 4.6 Vant 4 适配核查（2026-10-26 补测）

结论：**沿用 Vant 4，但不能用默认尺寸**。它按 375px 宽 / 14px 字号设计，PDA 要 56px 点按区与 72px 行高，中间必须有一层变量映射；映射只改变量，不改组件源码。

**版本与维护**

| 项 | 值 |
| --- | --- |
| 当前版本 | 4.10.2，2026-08-31 发布（距调研约 2 个月）；仓库最近推送 2026-10-22，提交节奏快于发版节奏 |
| 使用规模 | npm 周下载 53,136（2026-10-16 至 2026-10-22） |
| 许可证 | MIT |
| 直接依赖 | 3 个（`@vant/use`、`@vant/popperjs`、`@vue/shared`），无 GPL 类 |
| 体积 | 全量 245 KB min / **79.4 KB gzip**（Bundlephobia）；按需引入远低于此 |

**默认尺寸与 PDA 档位的差距（读 `packages/vant/src/**/index.less` 核实）**

| 项 | Vant 默认 | PDA 要求 | 说明 |
| --- | --- | --- | --- |
| 按钮高度 | `--van-button-default-height: 44px`；`large` 仅 50px | 56px | 必须覆盖 |
| 单元格实际行高 | 行高 24px + 上下内边距 10px = **44px** | 72px | 两个值都是硬编码字面量，只能覆盖变量 |
| 底部操作栏 | `--van-action-bar-height: 50px`，且 `content-box` | 64px | 安全区会在此之上继续加高 |
| 基础字号 | `--van-font-size-md: 14px` | 16px | 影响面最广的一项 |
| 圆角 | `--van-button-radius: 4px` | 跟随圆角令牌 | 需映射 |

**适配方式：一层变量映射，不封装组件、不用 ConfigProvider 当真源**

```css
/* 示意，落地位置为 packages/tokens 的 PDA 适配器 */
:root {
  --van-font-size-md: var(--font-size-base);
  --van-button-default-height: var(--control-height-md);
  --van-action-bar-height: var(--action-bar-height);
  --van-button-radius: var(--radius-md);
  --van-cell-vertical-padding: calc((var(--list-row-height) - 24px) / 2);
}
```

- 只写映射、不复制数值，令牌改动自动传导。
- 不用 `ConfigProvider.theme-vars` 作真源：它是 JS 对象，不随 `data-density` 变化，且会让同一数值出现两处。
- 暗色一期不做；将来用 `[data-theme="dark"]` 覆盖同一批 `--van-*`，不引入 `van-theme-dark` 类，避免两套主题开关。

**组件取舍**

| 类别 | 组件 | 理由 |
| --- | --- | --- |
| 直接用 | `van-nav-bar`、`van-cell`、`van-cell-group`、`van-field`、`van-button`、`van-popup`、`van-dialog`、`van-toast`、`van-notify`、`van-empty`、`van-loading`、`van-tag`、`van-sticky`、`van-list`、`van-pull-refresh`、`van-number-keyboard`、`van-picker`、`van-stepper` | 覆盖作业页八成需求 |
| 包装后用 | `van-action-bar` + `van-action-bar-button` | 需按 64px 重设并补底部占位 |
| 不用 | `van-floating-bubble` | 与「不做右下浮动按钮」冲突 |
| 不用 | `van-grid` 三列及以上 | 320px 下单格小于 88px，戴手套点不准 |
| 自建 | 见 §4.3 的 10 个组件 | Vant 不提供扫码输入、声振反馈、扫码结果条、已扫清单 |

**已知坑**

1. 若项目启用 px→vw 转换，56px 会随视口缩放，点按区保证失效；PDA 保持固定 px + 令牌，不做 vw 转换。
2. `van-action-bar` 是 `position: fixed` 且 `content-box`，页面必须自留底部占位，否则最后一行被遮；叠加安全区后总高会超过 64px。
3. `van-popup` / `van-dialog` 默认挂到 body，弹层会盖住操作栏；需要给弹层留底部间距或临时隐藏操作栏。
4. `van-cell` 的值区默认右对齐、单行省略，长条码会被截断；要用 `label` 承载换行内容。
5. 按需引入沿用 2026-10-22 结论：JS 走 tree-shaking，CSS 全量引一次，不引 `vant/es/<组件>/style` 这类内部路径。

## 5. R5 风险与待确认

### 5.1 风险

| 风险 | 影响 | 缓解 |
| --- | --- | --- |
| Android 9 WebView 忽略 `inputmode="none"`（库文档提示「旧 WebView 可能忽略」，另有单篇文章称需 Android 10+，**均未真机验证**） | 手工录入时软键盘遮挡内容 | 主路径不依赖输入框聚焦；真机验证后再决定手工录入的实现 |
| WebView 版本随固件锁定 | 新 CSS/JS 特性不可用 | 特性基线保守；关键能力做特性检测与降级；真机跑一次能力探针页 |
| 振动与音频需要用户手势解锁 | 首次扫码可能无声 | 在登录按钮/首个点击处解锁音频；声振失败不阻塞业务 |
| 扫描后缀由设备侧配置（CR/LF/TAB/无） | 后缀不一致会导致条码被拼进下一批或丢字符 | 交付时把后缀配置写进设备初始化清单；前端同时支持「有后缀」与「超时切批」两种模式 |
| 320px 宽度下长条码/长文案溢出 | 换行挤压、按钮被顶出屏幕 | 条码单行省略 + 点击查看全文；文案最多两行 |
| Vant 默认按 375px / 14px 设计（实测：按钮 44px、单元格 44px、操作栏 50px） | 320px 下偏挤，56px 点按区与 72px 行高都不满足 | 用一层 CSS 变量映射把 `--van-*` 指向令牌（§4.6），不在页面里逐个覆盖 |
| 2GB 内存与包体 | 首屏卡顿 | Vant 按需引入；不引图表库；首屏 JS 预算沿用 300KB gzip |
| 弱网重复提交 | 同一条码入账两次 | 幂等令牌 + 提交按钮提交中禁用 + 本地缓冲不清空直到收到成功 |
| 并发扫码响应乱序 | 界面显示与最后扫码不一致 | `useScanInput` 串行队列 + 请求序号，旧响应丢弃 |
| 实体九宫格按键与页面快捷键冲突 | 误触发 | 一期不映射物理键；若要映射，先进真机验证清单 |

### 5.2 待确认（未闭环前不进入实现）

1. **一期页面范围**：只做「商品查询」单页，还是直接上「任务执行」类页面？后者需要模板二与本地缓冲。
2. **是否允许装 WebView 壳 APK**：若近期需要广播扫码、厂商 SDK 调参或静默打印，则必须加壳，交互层需提前按「壳可注入 scan 事件」设计。
3. **声振反馈是否必须**：仓库噪音大时声音可能不可靠，是否接受「振动为主、声音为辅」。
4. **扫描后缀统一口径**：设备侧统一设 Enter、Tab，还是不设后缀由前端超时切批。
5. **是否一期就要离线队列**：若否，`ConnectionBadge` 只做提示不排队。
6. **连扫计数场景是否存在**（盘点类：同一码扫 N 次即数量 N）：决定 `ScanLineList` 是「一次一条」还是「同码累加」。
