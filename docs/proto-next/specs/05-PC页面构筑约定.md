# 05-PC 页面构筑约定

> 适用范围：本工作区所有会话，改动 `proto-next/pc/` 时必然适用。
> 起因：PC 端列表页反复返工——发明菜单树、自创列名、加统计卡片、手写大段 HTML、照搬静态分页。本文件把用户当时的裁决固化为可执行检查项。

## 1. 先查权威源，再动手

改任何 PC 页面之前，按顺序读这三处，**不允许凭印象或审美下手**：

| 顺序 | 来源 | 取什么 |
| --- | --- | --- |
| 1 | `specs/01-PC端设计规范.md` | 配色、字号、间距、圆角、结构硬约束 |
| 2 | `web 端原型模板_20261013.html` | 列表页骨架与组件形态（基线视觉权威） |
| 3 | `_archive/2026-10-29-handover/proto/admin_warehousedemo.html` | 菜单树、三级页签、列名、列宽、状态页签、按钮文案 |

**不得发明**：菜单名、层级、图标、列名、页签文案、按钮文案。全部从第 3 项逐字取。
**不得自创样式值**：图标尺寸、字重、间距一律照基线或旧产物，不按"看起来更好"改。

反面案例：旧版「总仓管理」有 7 个三级页，自行编成 4 个；图标自画 16×16（旧版是 24×24 / stroke 1.9）；旧版容器管理 18 列，自减为 5 列。

## 2. 页面骨架只有一套：`ListPage`

列表页一律用 `shared/ui/l3.mjs` 的 `ListPage`，骨架固定为：

```
page-card › statusTabs › queryPanel › actionBar › table-wrap/dt › pagerBar
```

**不加**：

- 统计卡片（`StatRow`）—— 基线列表页没有。计数放 statusTabs 的 count 或 actionBar 的 note。
- 页内大标题（`PageHeader`）—— 三级页签已表明当前页，标题重复。
- 自定义筛选栏 —— 用 `filters` 传，不写 `<div class="xxx-filter">`。

反面案例：曾给设备页加 6 张统计卡片 + 大标题 + 自绘筛选栏，与基线是两个观感。

## 3. 不拼 HTML，不写大段模板字符串

页面的职责是**取数与列定义**，结构交给 L3 组件。

- 页面模块只写 `columns` / `rows` / `filters` / `toolbar`，不 `return` 拼接的 HTML 片段。
- 客户端脚本落 `pc/src/shell/*.js`，由 `build.mjs` 读入并内联；不得写成 `build.mjs` 里的巨型模板字符串。
- 修改只落源目录，产物由 `node src/build.mjs` 生成，**不手工改 `dist/*.html`**。

反面案例：导航脚本 160 行写成模板字符串塞在 `build.mjs`，已抽为 `shell/nav.js`。

## 4. 分页必须真能切页

旧产物与基线模板的分页是**静态示意**（`共 N 条` + 禁用按钮，全量行铺开）。本原型的列表页要求可切页：

- `ListPage` 与 `BaseTable` 都支持 `pager`（默认开）、`pageSize`（默认 20）、`unit`。
- 行的列渲染留在构建期，全量 `<tr>` 带 `data-row-idx` 写入产物，脚本只做显隐（`shell/pager.js`）。
- 计数单位随页面取：条 / 件 / 行 / 个。

## 5. 文案：只留计数，不暴露实现

- **不写**：`数据源 shared/data/*.json`、`AGV 本期出界`、`工位即库位`、`不进硬件档案`、`点击「详情」查看八段` 这类实现说明、设计注解、操作指引。
- **保留**：抽屉/表单内的字段帮助文本（用户点开才看到，删了看不懂字段）。
- 副标题与表格 summary 只放计数。

### 5.1 汇报与说明材料：不写溯源，不写辩解

汇报正文只讲**要做成什么、为什么这样做**。以下四类内容会污染汇报链，一律删除：

| 类型 | 例子 | 为什么删 |
| --- | --- | --- |
| 溯源式辩解 | 「为什么早期认为必须挂 PC」「早期设计让员工扫二维码，这在物理上不成立」 | 讲的是我们过去怎么想错，评审不关心历史，只关心现在的结论 |
| 为设计找理由的推导 | 「管成独立档案只会引出解绑、调拨、随行等一堆规则」「物理约束绕不开」 | 用"如果不用就会很糟"反证，属于辩解口吻。改为直接陈述做法与边界 |
| 元话语 | 「前面讲的是…这一节讲…」「本节只保留方案说明部分」「不再重复」 | 作者对读者的编辑交代，正文不需要 |
| 出处引用 | 「依据 BND-01，已由用户裁决（2026-10-29）」「原话：…」「依据 PRD FR-HW-27 原文：…」 | 讲结论从哪来，不是结论本身。领导不关心文档编号与裁决日期 |

判据一条：**删掉这句话，读者对方案的理解会不会变少？** 不会变少就是噪音，删。

技术事实类否定句保留，如「Android 10 起第三方 App 读不到 IMEI」「一台打印机同一时刻只装一种介质」——那是必须说明的约束，不是辩解。

## 6. 空态的处理

- 菜单**保留**旧版完整结构，未实现的项**置灰不可点**（`.tab.is-off` + `disabled`），不进入"暂未设计"整页空态。
- 侧栏二级段点击时，跳到该段第一个**可点**的页面；整段皆未实现则不换页。

## 7. 布局硬约束

- 顶栏 54px 固定；侧栏 188px（收起 64px）固定，主区 `margin-left` 跟随。
- **页头三级页签钉住**，不随列表滚动。实现方式：`.app-shell` 用 `height:calc(100vh - var(--topbar-height))`（不是 `min-height`），`.main` 与 `.page-body` 补 `min-height:0`，使 `.page-body` 成为唯一滚动容器。
- **不放面包屑**。
- 抽屉与弹层必须挂 `body`，不得写在 `.page` 内（`.page{display:none}` 会连带隐藏，导致切页后按钮失效）。

## 8. 判断不了就来问

以下情形必须先问，不得自行决定：

- 旧产物与规范冲突，或旧产物没有对应实现。
- 要改动跨会话共用的文件（`shared/ui/tokens.css`、`l3.mjs` 的公共组件、`antd.css`）。
- 要删除可见内容（文案、页面、菜单项）。
- 菜单/页面范围有歧义（例如两个相似菜单项是否同一页）。

## 9. 交付前自查

- [ ] 菜单名、页签、列名逐字核对过旧产物。
- [ ] 没有 `StatRow` / `PageHeader` / 自绘筛选栏。
- [ ] 页面模块里没有拼接 HTML 大段字符串。
- [ ] 分页能切页，单位正确。
- [ ] 文案无实现说明与设计注解。
- [ ] `cd proto-next/pc && node src/build.mjs` 通过，`--check` ok。
- [ ] 改了 `shared/` 时，`proto-next/app` 也构建并 `--check`。
