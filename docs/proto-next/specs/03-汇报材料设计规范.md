# 汇报材料设计规范

> 适用范围：`reports/` 下的汇报 / 确认 HTML、周报、演示材料。
> 视觉标准来源：西之月 WMS TDD《库存模型设计.html》，2026-10-30 用户确认为既有标准。
> 空白模板：[`_模板-汇报.html`](../reports/_模板-汇报.html)。新材料从模板复制，不从头写。

本规范**只管汇报材料**。原型（`proto-next/pc`、`proto-next/app`）走 `01` / `02` 号规范，两套令牌互不通用——原型是紫系/绿系品牌色，汇报是蓝灰文档站色。

## 1. 格式与交付

- 单文件 HTML、双击即开、零依赖、零外链。不引 CDN、网络字体、图片外链。
- 图表用内联 SVG / CSS，不内嵌第三方渲染库（mermaid 等）。历史遗留的大体积材料不回刷，新材料不得再引入。
- 交付时同时给一份 Markdown 或图片，便于粘进邮件 / 企业微信。**但正文里不要写"本页是某某版本""方便粘进邮件"这类自述**。

## 2. 骨架五件套（缺一即不合规）

| 元素 | 类名 | 作用 |
| --- | --- | --- |
| 左侧固定目录 | `.sidebar` + `.layout` 两栏网格 | 长文档导航，滚动跟随高亮 |
| 眉标 | `.sec-kicker` | `01 / ENGLISH LABEL` 形式，给读者位置感 |
| 右侧角标 | `.count` | 一句话提要或一个数量，放在 `h2` 同行右端 |
| 页首导语 | `.lead` | 蓝底引言，一句话结论 |
| 白卡容器 | `.panel` | 所有表格、结论、正文都包在卡里，不裸贴背景 |

页首结构固定：`h1` 主标题 → `.sub` 日期范围 → `.lead` 结论 → 各 section。

## 3. 内容块（只用这六个类）

| 类名 | 用途 | 约束 |
| --- | --- | --- |
| `.panel` | 白卡容器 | 宽表格放 `.table-wrap` 里 |
| `.concl` | 结论条 | 三态：默认蓝=陈述；`.ok` 绿=已达成；`.warn` 黄=有风险/待办 |
| `table` | 数据表 | 12px，表头浅灰底，行间 `--soft` 分隔，末行去底边 |
| `.badge` | 状态标签 | `.high` 红=高优先；`.mid` 虚框=中；无修饰=普通 |
| `.link-list` | 交付件链接列 | 纵向排列，字号 12px |
| `.num` / `.prog` | 序号胶囊 / 进度数字 | 序号用蓝底圆角，进度用等宽数字右对齐 |

## 4. 禁止事项

以下每一条都来自实际返工，不是凭空设想。

### 4.1 不得自造容器

模板里没有的容器类（`.cards` / `.card` / `.hero` / `.grid` 等）一律不加。想表达"三个并列的点"，用一张三行表格，不要发明卡片。

> 事故：2026-10-30 周报把交付物表格换成三张自制卡片，用户指出"你完全违背了模板的样式，那个所谓的交付物的表格也没有了"。表格能横向比对进度与风险，卡片做不到。

### 4.2 精简文字 ≠ 删掉版式

删内容时只删文字，不删承载它的 `.panel` 白卡、`.concl` 结论条、`.sec-head` 结构。骨架是模板的价值所在。

> 事故：同一次周报，为省行数把 `.panel` 删了，表格直接贴灰底，分块感丢失。

### 4.3 类名不得跨用途复用

`.lead` 只给页首导语。卡片内的说明段落用普通 `<p>`，不要也挂 `.lead`——背景、边框、内边距会一起继承，出现"三段正文都被套上蓝底"的故障。

> 事故：`.card .lead` 只覆盖了字号和颜色，没覆盖 `background` 与 `border-left`，导致卡片正文变成蓝底色块。

### 4.4 不放无用交互与装饰

- 不放「打印 / PDF」按钮：`window.print()` 是浏览器自带能力，放页面上是多余入口。
- 不放「3 件交付 / 单文件 · 无外部依赖」这类标签行：读者不关心实现方式。
- 不放「本页是周报的可阅读版本，同目录还有 Markdown 版本」这类自述。
- 不放页脚技术说明（"单文件页面，不连接任何服务"）。
- 不写发出时间（"每周五下班前发出"）：这是流程约定，不是内容。

### 4.5 状态必须与事实一致

写 PRD、方案、评审结论之前，先看文件头部的状态字段。草稿就是草稿。

> 事故：五份 PRD 全部标记"草稿 / 草稿，待评审"，周报却写成"交付""规则已定""链路已打通""开发可照做"。用户指出后改为"草稿已出，待评审"。

### 4.6 不写与自己无关的事

周报只写本人负责的内容。别人的项目排期、他人负责的模块、与本人无工作关系的人名，都不进材料。

> 事故：周报写入了新商城项目的三个节点（11/6、11/15、11/20）与库存分层建议，用户指出"新商城履约链路跟我半毛钱关系没有"。另有已无工作关系的同事被列为负责人。

### 4.7 不把内部数据缺陷当风险

演示数据的重名、时间戳错乱、字段互驳，是自己造数据时的纰漏，属于内部返工项，不进"需要支持"。风险列只写对交付有影响的外部依赖。

> 事故：周报"需要支持"里写了"周敏重名核对 · EMP-201 与 EMP-108 是否同一人"，用户指出"这种模拟数据的，你都汇报？"。

### 4.8 术语要用读者能懂的说法

不堆内部黑话。判断标准：这句话给不参与本项目的同事看，他能不能直接懂。

| 不写 | 改写成 |
| --- | --- |
| 27 条待确认全部裁决 | 攒了 27 个没定下来的问题，这周一条条过完了 |
| 编号与硬件脱钩 | 编号按工号编，不跟着设备走 |
| 入口单值 | 一个人同一时间只能在一个终端上作业 |
| 三项数据阻断未消 | 任务数据有三个问题：超期判断 31 条对不上…… |

## 5. 篇幅

- **周报**：3~4 节，正文合计控制在 4 屏内（约 2400px @1440 宽）。
- **方案汇报**：6~8 节，单节卡片不超过 4 张。
- 表格行数超过 10 行考虑拆节，不要靠缩小字号硬塞。

## 6. 机器可检查项

两个脚本都要跑，缺一不可：

```bash
node tools/check-report-copy.mjs <file>        # 查写什么
node tools/check-report-structure.mjs <file>   # 查怎么搭
```

`check-report-copy.mjs` 查七类文案违规：溯源式辩解、出处引用、元话语、内部排期语言、自造词、辩解式推导、数量盘点。

`check-report-structure.mjs` 查六类结构问题：

| 规则 | 检查内容 |
| --- | --- |
| K | 骨架五件套齐全（`.sidebar` / `.sec-kicker` / `.count` / `.lead` / `.panel`） |
| L | `.lead` 全文件仅 1 处，且位于 `<header>` 内 |
| C | 不出现模板外的容器类名（`card`/`cards`/`table-wrap` 以外的卡片、栅格、hero 类） |
| S1~S5 | 无打印按钮、无 `window.print`、无实现方式自述、无双版本自述、无流程时间约定 |
| X | 零外链 |
| T | 含 `<title>` |

**历史材料豁免**：`任务中心思路.html`、`任务中心看板调研.html`、`硬件接入管理.html`、`设备管理思路.html` 四份按旧规范产出，用户裁定不刷，已在脚本内登记豁免（豁免骨架与装饰类检查，外链与 title 仍查）。新增材料不在豁免名单内。

## 7. 出图

需要图片时用无头浏览器渲染，不要手工截图：

```bash
"/Applications/Google Chrome.app/Contents/MacOS/Google Chrome" \
  --headless --disable-gpu --no-sandbox --hide-scrollbars \
  --force-device-scale-factor=2 --window-size=1440,2400 \
  --virtual-time-budget=4000 \
  --screenshot=out.png "file:///绝对路径/材料.html"
```

渲染后按背景色裁掉底部多余空白。2 倍缩放保证 Retina 屏清晰。
