# 04-环境论断核查约定

> 适用范围：本工作区所有会话的 agent。
> 起因：本会话内多次出现「把单一便捷来源的输出当事实」的错误（插件简介页、工具的一行状态字段、凭印象断言目录结构）。本文件是防复发约定。

## 1. 单源不采信

任何工具/文档/状态面板给出的**一行结论**，只当「一条主张」，不当结论。

- 插件收录页、README 摘要、`--version`、`doctor` 输出等，都是间接来源。
- 涉及用法的事实，以**真实文档 / 源码**为准（例如 `SKILL.md`、包内 `docs/`）。
- 涉及环境的事实，以**本会话真跑过的命令原始输出**为准。

## 2. 否定结论须双证据，并限定作用域

说「本机缺 X / 没有 X / 不支持 X」之前：

1. 必须有**两种独立探测**都指向缺失（例如包的 `require.resolve` + 系统 `which` + 缓存目录三者中的两种）。
2. 必须**写明作用域**：正确表述是「插件的 Node 解析路径下找不到 X」，不是「本机缺 X」。

反面案例：工具 `doctor` 输出 `playwright=missing`，实际本机有 Python 版 Playwright 与完整浏览器缓存——`missing` 只反映该工具的窄探测路径。

## 3. 论断须可回溯到命令

每句关于环境的事实陈述，都要能指回**本次会话执行过、且核对过原始输出**的命令。

- 禁止凭模型印象、默认目录约定、训练记忆断言「某目录/文件存在」。
- 拿不准就先 `ls` / `find` / `grep`，再开口。

## 4. 高危句自查

以下句式是本工作区出错最集中的位置，写出前停一拍，确认证据等级：

- 「已安装 / 已配置 / 已注册」
- 「本机缺 X / 不支持 X」
- 「 X 不存在 / 没有 X」
- 「版本是 X」（须来自真跑的版本命令）

## 5. DSH profile 陷阱（本机实测）

本机有**两个 profile**：

| profile | 谁在用 | 内容 |
| --- | --- | --- |
| `~/.dsh/profiles/desktop` | **桌面 App**（用户日常界面） | `workbuddy-to-dsh` + 多个 `experimental-*`；patch 含 `ui-chat` / `ui-settings` |
| `~/.dsh/profiles/web` | `dsh web` 命令行启动的网页版 | 第三方插件（dsh-obsidian、avoid-ai-writing-cn、dsh-inspiration-deck-workshop、dsh-prompt-optimization-master） |

**铁律**：`dsh plugin --profile X add` 的 X 必须与实际运行环境一致。装到 `web` 的插件**不会**出现在桌面 App 里；反之亦然。说「插件装好了」之前，必须确认 profile 与目标运行环境一致。

证据来源：`ls ~/.dsh/profiles/`、`~/.dsh/profiles/*/package.json` 的 `dsh.profile.bundles`、各自 `cordis.patch.yml`。
