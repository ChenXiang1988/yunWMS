## A 已裁决，但落地方式要确认

A1 一人一单元已定。现在数据是「一台终端一行」，共 101 行，其中 85 行有人、16 行无人。这 16 行怎么处理？
- A 删掉，资源池只保留有人的行（85 条）
- B 保留但改成「未启用入口」另置一处，不进资源池
- C 保留在原表，页面加筛选默认隐藏

> 建议 A。一人一单元下，没登录就没有单元，16 行是「接入即单元」旧口径的遗留。删掉后页面第一眼数字从 101 变 85，与实际在岗人数一致。

A2 单元编号怎么生成？现为 `EU-HP-001`（按终端派生），一人一单元后应跟人走。
- A 改 `EU-EMP-001`，按工号派生，换入口不改号
- B 沿用 `EU-HP-*`，只在新建时用新规则
- C 保留现有编号不动，规则只约束新增

> 建议 A。编号跟人走才符合「换机不换单元」，否则换一次入口就要换一次号，任务外键全断。代价是 101 条编号要迁移，任务表目前只存类型码 `execUnitCode`、没有具体单元号，所以迁移面比想象小。

A3 类型码改不改？现为 `EXEC-PDA`（把入口写进了类型）。
- A 改 `EXEC-HUMAN`（人型）、增 `EXEC-AUTONOMOUS`（自主设备型，仅登记）
- B 保留 `EXEC-PDA`，只在文档里说明语义
- C 改 `EXEC-HUMAN` 但暂不增自主设备型

> 建议 A。类型名里带 `PDA` 会持续误导：手机单元现在也叫 `EXEC-PDA`，靠 `typeLabel` 区分。自主设备型只登记类型、不造数据，成本几乎为零。

A4 PC 算不算单元入口？PRD 写「一人最多一 PDA 单元加一 PC 单元」，数据里 PC 单元 0 条、PC 台账 5 台。
- A 一台 PC 都不产生单元，PC 只是入口，页面「入口」列显示 PDA / 手机 / PC
- B 补 5 条 PC 单元做演示
- C 本期不体现 PC

> 建议 A。一人一单元下 PC 本来就不该有独立单元。入口列显示该单元**当前唯一**的入口；用 PC 作业时，入口就是 PC，PDA 不再同时有效。

A5 换机怎么表达？PRD 现写「旧单元释放、新单元生成」（FR-EU-09），与「换机不换单元」直接冲突。
- A 改 PRD：换机只换入口，单元不变，任务归属不变
- B 保留「释放+重建」，靠任务中心把任务续到新单元
- C 两个都写，按场景区分

> 建议 A。`DOC-SPC-006` 的 FR-TC-43「换机时任务跟人不退回任务池」本来就对，是执行单元 PRD 的模型没跟上。改 PRD 比改任务中心便宜。

A6 区域、班次降为运行属性后，一条记录怎么表达「一个人跨区」？
- A 单元只记当前区域，历史区域进日志
- B 单元支持多区域，界面显示「主区域 + 兼管」
- C 区域不进单元，只在任务上体现

> 建议 A。B 会让「按区域筛资源池」变成集合匹配，页面与派工都要改；C 会让资源池失去区域维度。A 最省，且与「区域随时可变」的裁决一致。

## B 执行单元页要做成什么样（这是本轮最要紧的一组）

B1 页面回答什么问题？你已明确：**有多少可执行资源、多少受限、负载多少**。三个数字怎么呈现？
- A 状态页签承载：「全部 85 / 可派 81 / 在办 4 / 受限 1」，工具栏写一行汇总
- B 页面顶部加一行纯文字计数条（需改 05 号规范）
- C 另开「资源概览」页，执行单元页保持台账

> 建议 A。05 号规范第 2 节明令禁止 `StatRow` 统计卡片，B 要走改规范流程；C 会多一个页面，违背一页管一件事。A 零规范改动。

B2 18 列里有 6 列在新模型下失去意义：类型（全同值）、设备编号、登录态、设备态、下发通道、登录时间。怎么处理？
- A 压缩到 9 列：主体 / 入口 / 区域 / 班次 / 在办 / 负载 / 受限原因 / 最近活动 / 操作
- B 保留现有列，只把「类型」换成「入口」
- C 全表重排，由你逐列指定

> 建议 A。「设备编号」应改为「当前入口」，**单值**（任一时刻只有一个）；「受限原因」直接给原因，不给「状态」这种要二次解读的值。

B3 负荷（`load`）按什么算？现在是造数：4 个在办的人负载 0.15～0.30，81 个空闲的人最高 0.90——最忙的最低、最闲的最高。
- A 在办强度：在办任务数 ÷ 并行上限（当前上限 1，只有 0/1 两值）
- B 工时利用率：当班已用工时 ÷ 当班可用工时（缺班次起止与标准工时）
- C 队列积压：已派未开工 + 在办
- D 派工评分输出：由派工算法算完写回，页面只读

> 建议 B 表达、C 兜底。但要看你的管理直觉：想表达「这个人忙不忙」选 B，想表达「这个人手上压了多少活」选 C。A 最省事但几乎没有区分度。

B4 「受限」是独立轴还是状态值？`EU-HP-005`（赵强）同时「在办」和「入口离线」。
- A 独立轴：能否接新任务 = 可派 / 受限；在办另作标记
- B 单轴四态：可派 / 在办 / 不可派 / 已释放（PRD 现写法，两者互斥）
- C 三轴：在岗轴 + 在办轴 + 入口轴，页面各给一列

> 建议 A。真实业务里「在办」和「受限」会叠加，四态互斥表达不了。这一条会连带改 PRD 第 8.5 节的状态表。

B5 能力与缺口要不要在页面上出现？PRD 第 9 章要求列「能力、缺口」，实现里既无字段也无列。
- A 本期不上，PRD 同步降级为「后续」
- B 补字段并按 PRD 做三态（齐 / 走兜底 / 缺）
- C 只做缺口筛选（「只看有缺口的」），不单列能力

> 建议 A。能力依赖外设在线状态，而外设数据（`attachedPrinters`）只在 PC 行里有、且未接入探活，做出来是假能力。

B6 登录记录页做不做？PRD FR-EU-14 要求「按时间查历史会话」，原型里 0 实现。
- A 本期不做，PRD 标为后续
- B 用 `exec-units.json` 的 `logs` 字段做一个只读列表
- C 单独建会话表

> 建议 B。`logs` 已有登录/登出痕迹，做一个只读列表成本很低；C 要新建数据文件，本期没有登录写入链路，建了也是空表。
