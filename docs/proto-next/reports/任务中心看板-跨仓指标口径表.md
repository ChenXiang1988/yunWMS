本表只做一件事：把每个看板指标写成**可核对的一行**——分子、分母、时间窗、取哪个字段、能不能算、缺什么。指标定义冲突时以本表为准。

## 一、使用说明

1. **口径唯一**。同一指标在单仓视图与全网视图必须同源同式。汇总层只做加权合并，**不重新定义公式**，否则单仓与总部会出现两个数。
2. **分子分母必存**。事实表存 `numerator` 与 `denominator` 两列，不存单独比率。三个仓各 90% 不能加权成 90%，必须回分子分母重算。
3. **缺失显式**。任何聚合结果旁标「覆盖 x/n 仓」。缺数据的仓不得静默按 0 参与平均。

## 二、公用维度与公用字段

### 2.1 五个公用维度

| 维度 | 字段 | 取值来源 | 说明 |
| --- | --- | --- | --- |
| 仓 | `warehouse` | 任务行直取 | 汇总维度，同时是行级权限过滤键 |
| 工序类别 | 表名派生 | `上架` / `移库` / `盘点` | 三类源文件分表，不在行内 |
| 任务状态 | `status` | `pending` `putaway` `moving` `counting` `exception` `completed` `cancelled` | 未终态集合 = 前五值 |
| 时间窗 | `periodStart` / `periodEnd` | 派生 | 支持日 / 周 / 月同源 |
| 数据覆盖 | `coverage` | 派生 | 该仓该期是否有完整回传 |

### 2.2 未终态的定义（全表共用）

```
未终态 = status ∈ { pending, putaway, moving, counting, exception }
终态   = status ∈ { completed, cancelled }
```

实测：136 行中未终态 77、已完成 54、已取消 5。**已取消不计入任何分母**，除「取消率」一项。

## 三、指标定义表

字段列写法：`字段名` 表示任务行直取；`派生(…)` 表示需计算。可算性三档：**可直接算** / **需修数** / **不可用**。

### 3.1 结果层（跨仓可对比，须归一化）

| 编号 | 指标 | 分子 | 分母 | 取数字段 | 可算性 | 风险与缺口 |
| --- | --- | --- | --- | --- | --- | --- |
| M-01 | 准时完成率 | 未超期且已完成 | 未取消任务 | `status` `slaStatus` | 需修数 | `slaStatus` 与 `deadlineDate` 冲突，31/77 不一致，见 §5.1 |
| M-02 | 一次做对率 | 无异常记录的已完成任务 | 已完成任务 | `status` `exceptionLogs[]` | 可直接算 | 实测 34/54 = 63.0%；`exceptionLogs` 覆盖 49/136 行 |
| M-03 | 异常关闭率 | `exceptionLogs[].closed = 是` | 全部异常记录 | `exceptionLogs[]` | 可直接算 | 实测 25/50；无关闭时间戳，只有布尔 |
| M-04 | 异常关闭时长 | Σ(关闭时间 − 发生时间) | 已关闭异常数 | `exceptionLogs[].occurredAt` `exceptionTakenAt` | 不可用 | 无关闭时间字段；`exceptionTakenAt` 仅 12/25 有值 |
| M-05 | 单任务处理时长 | Σ(`completedAt` − `startedAt`) | 有效样本数 | `startedAt` `completedAt` | 不可用 | 中位 500.8 小时，54/54 全部超 24 小时，见 §5.2 |
| M-06 | 任务取消率 | `status = cancelled` | 全部任务 | `status` | 可直接算 | 实测 5/136 = 3.7% |

### 4.3 数量口径不可跨类相加

| 工序 | 数量字段 | 单位字段 | 可用性 |
| --- | --- | --- | --- |
| 上架 | `planQtyTotal` + `putawayProgress` + `skuDoneCount` | `qtyUnit`（49/55） | 件数与 SKU 行两套口径并存 |
| 移库 | `planQtyTotal` + `moveProgress` | `moveUnit`：按托 73 / 按箱 16 | **两种单位混在同一列**，求和前必须分组 |
| 盘点 | 无数量字段 | 无 | 只有 `skuCount` / `countedSkuCount` / `diffSkuCount` |

结论：跨类只能比**任务条数**与**SKU 行数**，不能比件数。若要比件数，需对移库按托/箱设换算系数（复杂度加权），系数来源待定。

## 五、口径冲突与待修项

### 5.1 阻断项一：超期口径冲突

- 现状：未终态 77 条中，字段标「已超期」12、「临期」17、「正常」48。
- 上架表自带 `slaDefinition`，写明判定基准为快照 2026-10-09 12:00、临期阈值 4 小时、判定由上游下发且页面不重算。
- 按该规则重算：**31 条与字段不一致**，分布在全部五个仓。其中临期↔正常互判 15 条（字段「正常」应为「临期」6 条、字段「临期」应为「正常」9 条）；正常↔已超期互判 16 条（字段「正常」应为「已超期」8 条、字段「已超期」应为「正常」8 条）。
- 处理建议：二选一并写入本表 ——（A）读字段，接受与事实的偏差；（B）重算并回写数据。
  **建议 B**，理由：任何准时率指标都以它为分母，口径不稳则整套看板不可用。

### 5.2 阻断项二：时长不可用

- 54 条已完成任务中，`completedAt` 100% 晚于 `deadlineDate`；中位时长 500.8 小时（约 21 天）。
- 根因：完成时间被整体重排到最近七天（10-24 至 10-30），开始时间仍是十月初。
- 影响：M-05 及一切节拍、产能、达成率类指标全部失效。
- 处理建议：修数（把 `startedAt` 与 `completedAt` 一并移到同一窗口）后再启用时长类指标。**在修好之前，看板不展示任何时长数字。**

### 5.3 阻断项三：状态与派工字段互驳

| 现象 | 实测 | 影响 |
| --- | --- | --- |
| 未终态但派工已完成 | 2 条（STC-0015、STC-0020） | M-07 分母含矛盾行 |
| 已推送待领取但无作业员 | 6 条（RLT-0045 至 0063 区间） | 「待指派」口径不唯一 |
| `operatorName` 为空 | 19/136 | 未填人的任务无法按人聚合，人效与负荷统计漏计 |
| `dispatchStatus` 词表不统一 | 上架 6 种、移库 8 种、盘点 3 种，三类并集 11 种 | 跨类统计该列需先做词表映射表 |

处理建议：先建一张 `dispatchStatus` 映射表（约 12 个原始值 → 5 个规范值：待下发 / 待指派 / 待领取 / 执行中 / 已结束），再定 `operatorName` 与 `execSubject` 的语义边界——前者应只放人，设备走 `execSubject`。

## 六、归一化与分组规则

### 6.1 分组

| 组 | 仓 | 是否进运营对标 | 理由 |
| --- | --- | --- | --- |
| 实体仓组 | 华东、华南、华北 | 是 | 自有仓，有执行单元 |
| 名义仓组 | 华西（虚拟）、西南（三方） | 否，单列覆盖维度 | 0 执行单元，运营条件不可比 |

### 6.3 上榜门槛

| 规则 | 取值 | 理由 |
| --- | --- | --- |
| 单指标样本量下限 | 5 | 西南仓完成样本 1 条，100% 无统计意义 |
| 分母为 0 的处理 | 显示「—」，不进排名 | 名义仓 0 单元，负荷比无定义 |
| 排名依据 | 改善幅度，不排名绝对值 | 各仓规模差一个数量级 |
| 展示单位 | 比率两位小数；样本量随比率同列显示 | 避免单个比率被误读为可靠结论 |
