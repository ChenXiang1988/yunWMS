## 一、基本前提

### 1.1 设备身份的可获取范围

| 标识 | 普通 App 可获取 | 说明 |
| --- | --- | --- |
| IMEI | 否 | Android 10 起 `getImei()` 抛出 SecurityException |
| 序列号 | 否 | `Build.getSerial()` 自 Android 10 起受限 |
| MAC 地址 | 否 | Android 6 起返回固定值 `02:00:00:00:00:00`，Android 10 起按网络随机化 |
| Android ID | 是 | 绑定应用签名与用户，重装或恢复出厂后变化 |
| OAID | 是 | 用户可重置 |

IMEI 被限制的原因：访问不可重置标识需 `READ_PRIVILEGED_PHONE_STATE`，该权限为签名级，Google Play 渠道的第三方应用无法声明。

但有例外，按应用身份区分：

| 应用身份 | 能否读 IMEI | 条件 |
| --- | --- | --- |
| 普通第三方 App | 否 | 无法声明 `READ_PRIVILEGED_PHONE_STATE` |
| **设备所有者 / 配置文件所有者（DO/PO）** | **是** | 仅需 `READ_PHONE_STATE` |
| 系统签名预装应用 | 是 | 持有 `READ_PRIVILEGED_PHONE_STATE` |
| 特殊运营商权限应用 | 是 | 不需要额外权限 |

结论：**Device Owner 是企业 App 合法获取 IMEI 的唯一常规路径**，不需要系统签名。公司机统一做 DO 后可读 IMEI；BYOD 手机不可读。厂商 ROM 存在差异，上线前须真机验证。

### 1.2 打印机接入形态

打印机支持 USB、网络直连、云打印三种接入形态。网络直连与云打印不依赖 PC，详见第七章。

## 二、核心定义

设备管理管的是设备可用性，不涉及资产计价。

四个动作：**认得出 → 绑得对 → 看得见 → 换得快。**

---

## 三、设备管理与资产管理的边界

| | 资产管理 | 设备管理（本文） |
| --- | --- | --- |
| 回答什么 | 值多少钱、该不该退役 | 能不能用、谁在用、坏了怎么办 |
| 核心字段 | 资产编号、原值、折旧、报废审批 | 设备标识、绑定关系、在线状态、故障换机 |
| 时间尺度 | 年 | **分钟** |
| 出错后果 | 账目不平 | **作业停线** |
| 手机是否纳入 | 否 | **是** |

三类设备的档案均不含资产编号、折旧与报废审批。

## 四、管理范围

| 实物 | 定位 | 关键点 |
| --- | --- | --- |
| 安卓手机 | 作业终端 | 与 PDA 同源 |
| PDA | 作业终端 | 主力作业设备 |
| 打印机 | 独立设备 | 支持网络直连与挂 PC 两种形态 |

**纳入范围**：员工随身携带的作业终端、工位上与作业直接相关的打印设备。

**不纳入范围**：资产编号、折旧、报废审批、AGV、摄像头、称重机、扫码枪、键鼠显示器、采购审批。

## 五、身份链路

公司机与自带机并存，身份分两条链路。

### 5.1 受管设备（公司机）

前提：统一采购后配置 Device Owner 或接入 MDM。

| 能力 | 具备 |
| --- | --- |
| 读取 IMEI / 序列号 | 是，硬件级 |
| 强制安装、禁止卸载 | 是 |
| 锁屏、禁相机、禁 USB | 是 |
| 远程定位、远程擦除 | 是 |
| 防止换机冒用 | 是 |

**身份主键：IMEI。**

### 5.2 自带设备（BYOD）

| 能力 | 具备 |
| --- | --- |
| 读取 IMEI | 否 |
| 远程擦除 | 否 |
| 强制安装、禁止卸载 | 否 |
| 锁屏、禁相机、禁 USB | 否 |
| 应用级指纹 | 是 |

**身份主键：App 生成的设备 UUID**，存于 Android Keystore，随账号绑定登记。

**技术限制须明确**：UUID 存于应用私有区，员工清除 App 数据或卸载重装即变，恢复出厂亦变。因此 UUID 只能识别、不能认证。真正的认证凭据是账号与服务端令牌，重新登录须走二次验证。

#### 5.2.1 管理对象由设备转为账号

BYOD 场景下无法管控设备本体，管理对象下沉到账号。设备只是作业入口，认证与授权发生在账号层。

| 维度 | 公司机（DO） | 员工自带机（BYOD） |
| --- | --- | --- |
| 管理对象 | 设备本体 | 账号与作业授权 |
| 身份主键 | IMEI（硬件级） | 账号 + 应用 UUID |
| 能否强制 | 能 | 不能 |
| 能否远程擦除 | 能 | 不能，属员工私人财产 |
| 可控范围 | 锁设备、禁功能、擦数据 | 限定谁可作业、可作业到哪 |

#### 5.2.2 五个动作

**一、绑定：以账号为准，不依赖硬件**

员工登录后账号即为凭据。首次登录时 App 生成 UUID 存 Keystore 并上报，系统记为「该账号的常用设备」。同时记录设备型号、系统版本、App 版本作为辅助识别。不采集 IMEI、通讯录、相册、位置。

**二、换机识别：可发现，不阻断**

员工更换自有手机属正常行为，系统不做阻断，只做识别。

| 情形 | 系统反应 |
| --- | --- |
| 同账号新设备登录 | 记为「新设备」，要求二次验证（短信或人脸）后放行 |
| 短期内频繁换设备 | 触发风控，要求主管确认 |
| 同一设备登录多个账号 | 允许，各账号分别记录绑定 |
| 刻意冒用（借用他人手机） | 二次验证与风控拦截，UUID 不可作为认证依据 |

**三、作业范围：在服务端限制，不在设备上限制**

设备侧无法管控，但服务端可约束授权范围。

- 仅可进入授权仓与授权区域，由服务端校验，与设备无关
- 敏感操作（改价、删除、越权查询）在 App 内二次认证
- 离开授权区域后心跳中断，该单元自动退出派工候选

**四、隐私边界：须写入制度**

公司无权在员工私人设备上采集与作业无关的信息。App 与《BYOD 使用告知书》须一致声明。

| 不采集 | 原因 |
| --- | --- |
| IMEI | 敏感个人信息，非公司资产，采集无合法基础 |
| 通讯录、相册、位置 | 与作业无关 |
| 不远程擦除 | 员工私人财产 |
| 不静默安装 | 越界 |

| 仅采集 | 用途 |
| --- | --- |
| 账号与登录记录 | 认证与审计 |
| 设备型号、系统版本、App 版本 | 兼容性与问题定位 |
| 作业日志与扫描流水 | 业务留痕 |

**五、离职与丢失：服务端解绑，不接触设备**

| 情形 | 处理 |
| --- | --- |
| 员工离职 | 服务端注销账号并解绑设备，App 下次联网即失效 |
| 员工换手机 | 新设备二次验证后重新绑定，旧设备绑定作废 |
| 手机丢失 | 服务端强制下线该账号。无法擦除，只能切断访问 |
| 员工拒绝安装 App | 改配公司机，或调整岗位 |

BYOD 的回收依靠服务端解绑，不依赖对设备的操作。

#### 5.2.3 三类设备混用建议

| 岗位类型 | 建议 | 理由 |
| --- | --- | --- |
| 高频作业（拣货、复核、打包） | 公司机 + DO | 强管控、使用时长高、设备易损 |
| 低频或临时（盘点支援、主管巡视） | BYOD | 使用频次低，无需配机 |
| 管理层 | BYOD 或 PC | 以查看为主，不承担作业 |

### 5.3 管理深度的决定因素

设备管理深度取决于设备所有权。统一采购并配置 Device Owner 可获得完整管理能力；仅安装应用时，可管理的范围限于账号与设备的绑定关系。

DO 配置的前置条件与限制：

| 项 | 要求 |
| --- | --- |
| 设备状态 | 必须为出厂状态或已恢复出厂，已激活设备无法直接设为 DO |
| 交付流程 | 采购 → 开箱不激活 → 配置 DO → 交付员工 |
| 解除能力 | App 须内置解除设备所有者功能，否则恢复出厂亦无法移除管控 |
| 国内品牌 | 华为须申请 MDM 商用权限（审核 1–2 个工作日）；小米走政企服务；三星 Knox 支持标准 DO；其余品牌须真机验证 |

分期建议：

| 期 | 内容 | 覆盖范围 |
| --- | --- | --- |
| 一期 | 设备编号 + 二维码扫码绑定 + 指纹校验 | 全部设备，含 BYOD，不依赖 DO |
| 二期 | DO 支持，公司机自动读 IMEI 无感校验 | 公司机体验优化 |

一期完成后设备管理即可运行。二期为体验提升，不是前置条件。

## 六、四个动作

### 6.1 认得出（身份）

规则：**一个身份对应一台实物，生成后不可修改。**

- 公司机：IMEI + 序列号
- 自带机：设备 UUID + 型号
- 打印机：序列号 + IP / MAC（网络机）、序列号（USB 机）

**指纹校验**：上报值与登记值不一致时拒绝进入作业界面。同型号设备外观一致，拿错为常见情形。

### 6.2 绑得对（绑定关系）

绑定的主键是**本模块生成的设备编号**，不是 IMEI。三类设备的绑定对象不同，不能混为一谈。

| 设备 | 绑定对象 | 为什么 |
| --- | --- | --- |
| 手机 / PDA | **人 ↔ 设备** | 随身设备，跟着人走。谁登录就是谁在用 |
| PC | **工位 ↔ 设备** | 固定在工位，一个工位多人轮班用。人不绑电脑 |
| 打印机 | **工位 ↔ 设备**（USB 形态另挂 PC） | 跟着工位走，不跟人走 |

**关键差别**：手机是人的工具，PC 与打印机是工位的固定资产。这个区分决定了换班时要不要操作设备——手机要换绑，PC 与打印机不用动。

#### 手机与 PDA：靠激活码登记，不扫自己的码

身份由 App 运行时自动读取并上报（受管设备读 IMEI 与序列号，自带设备读应用 UUID 与型号），人不需要拿设备扫自己机身的码——那在物理上不成立。

人要做的是输入**激活码**：

1. **建档**（管理员）：建型号与单台设备，生成设备编号与资产编号，打印二维码贴机身。序列号与 IMEI 作为档案字段录入。
2. **发码**（管理员）：在 PC 侧为该设备生成一机一码的激活码，当面告知或内部渠道发送，**不贴在设备上**。
3. **激活**（员工）：本机 App 自动显示自己的设备编号与 IMEI（或 UUID），输入激活码完成登记。
4. **换机**：登出旧机，在新机登录并输入新激活码。任务跟人走，不跟设备走。

二维码的用途只剩盘点与核验时扫码查详情，不承担绑定。

#### PC：装本地代理，读主板序列号

浏览器拿不到主板序列号，这是硬约束。**PC 识别必须装本地代理。**

```
浏览器（WMS 网页）
   ↕ 本地回环 127.0.0.1
pc-agent（装在这台电脑上）
   ↕ 读硬件
主板序列号 / BIOS UUID
```

代理上报主板序列号，与档案登记值比对。一致则放行。这是 PC 端唯一可靠的机器识别手段。

PC 登录只用账号密码，不做人脸——人固定在工位，风险低于随身设备。

#### 打印机：跟着工位，USB 形态跟 PC

| 形态 | 挂在哪 | 定位依据 |
| --- | --- | --- |
| USB 接 PC | **不单独管**，作为 PC 的配置项 | 随 PC |
| 网口直连 | 挂工位 | IP + 工位登记 |
| 云打印 | 挂工位 | 云设备号 + 工位登记 |

USB 打印机不建独立档案，不占资产编号。理由三条：它没有账号、不能独立联网、坏了整机换。管成独立资产只会引出解绑、调拨、随行三类规则，都是负担。

管住 PC 就管住了 USB 打印链路。PC 档案里记「这台电脑接着什么打印机、装的什么介质」，PC 调拨时跟着走。

网口与云打印机不同——它们能独立联网、有独立地址，必须作为独立设备管理。

#### 工位就是库位

打包台、复核工位、收货工位，在系统里都是**库位的一种类型**（`binType=工位`）。这样工位有唯一编号，能反查「这个工位上有什么设备」「谁在这个工位登录」。

三层关联是设备管理的核心资产：

| 绑定 | 含义 | 断开的后果 |
| --- | --- | --- |
| 手机 ↔ 人 | 谁在用这台随身设备 | 无法确定任务归属人 |
| PC / 打印机 ↔ 工位 | 这台设备固定在哪 | 找不到设备，打印任务发错位置 |
| USB 打印机 ↔ PC | 挂在哪台主机上 | 打印发不出去 |

**一人同一时刻只能有一个执行单元。** 更换终端时先登出旧单元，旧单元释放、新单元生成，**任务归属人不变**。

### 6.3 看得见（在线状态）

**在线三态**：在线 / 离线 / 故障。

| 设备 | 探活方式 |
| --- | --- |
| 手机、PDA | App 心跳上报 |
| 网络打印机 | 直探：SNMP 或 ZPL `^HH` / `~HS` |
| USB 打印机 | PC 代探；PC 离线时记「未知」，不判为离线 |

PC 离线时打印机状态未知。若直接判为离线，每日将产生大量无效告警，运维关闭告警通道后监控能力失效。

设备状态用于派工约束：候选池只取在线单元，离线单元不进入候选。

### 6.4 换得快（故障与换机）

作业中 PDA 断电的处置：

1. 在办任务转「受阻」，**不退回任务池**
2. 旧单元转不可用，**不删除**
3. 作业员以备用机登录，旧单元结束、新单元生成
4. 任务重绑新设备，**负责人不变**，单元历史追加新旧两台设备

在办任务不退回任务池：退回后其他作业员可能从同一库位重复拣货，且该作业员已走过的位置与已扫描行将丢失。任务归属人，不随设备迁移。

## 七、工位：设备挂在哪里

设备管理最容易忽略的一环：设备本身登了记，但"它现在挂在哪"没有结构化的答案。工位就是解决这个问题的。

### 7.1 工位是库位的一种

库位类型里有一类叫「工位」，与存储位、拣货位、暂存位并列。它不存货，只承载设备与人。

```
库位 EC-PICK-A-WS-02（华东仓 · 复核工位）
  ├── PC-01        工位主机（主板序列号 MB-0001）
  ├── P1           网口直连打印机（独立挂工位）
  └── P3           USB 打印机（挂 PC-01）

人（张三）— 登录时记录所在工位，不绑 PC
```

### 7.2 三层结构

| 层 | 是什么 | 举例 |
| --- | --- | --- |
| 工位 | 物理位置，库位的一种 | EC-PICK-A-WS-02 |
| 主机 | 工位上的一台 PC | PC-01 |
| 外设 | 挂在主机或工位上的设备 | P3（挂 PC-01）、P1（挂工位） |

**为什么这层结构必要**：仓库里有几十个工位、上百台设备。没有工位这一层，问"3 号打包台的打印机是哪台"只能靠人记或翻 Excel。

### 7.3 四条硬规则

| 规则 | 违反后果 |
| --- | --- |
| 设备所在仓必须与工位所属仓一致 | 湖南仓的打印机挂到华东工位，调度时会发错 |
| USB 打印机必须与其 PC 同工位 | 打印机挂在 A 工位、PC 在 B 工位，打印打到别处 |
| 工位解绑主机前，须先清空其 USB 打印机 | 主机搬走，打印机变孤儿 |
| 一台打印机同时只挂一个位置 | 重复挂载后不知道该往哪打 |

### 7.4 换班与换机的区别

这是工位模型带来的最大简化：

| 情形 | 需要操作设备吗 |
| --- | --- |
| 张三换班给李四（同一工位） | **不用**。工位不变，设备全不动 |
| 工位的 PC 坏了换一台 | 改工位的 PC 绑定，人不感知 |
| 员工换了自己的手机 | **要**。手机绑人，须重新激活 |

## 八、打印机

### 8.1 三种接入形态

| 形态 | 连接方式 | 是否依赖 PC | 代表机型 | 探活 |
| --- | --- | --- | --- | --- |
| USB 本机接 | USB → PC 代理 → 系统 | 是 | 仅具备 USB 接口的机型 | PC 代探 |
| 网络直连 | 网口 / WiFi 入网，系统向 `IP:9100` 发送 RAW TCP 指令，下发 ZPL / TSPL | 否 | Zebra ZD421（10/100 以太网、WiFi 802.11ac）、TSC 全系、Brother QL-1110NWB | SNMP / ZPL `^HH` 直探 |
| 云打印 | 打印机主动连接云端拉取任务（HTTP 轮询或 MQTT 长连） | 否 | Star CloudPRNT、佳博云、快麦、映美云、快递100 | 云平台回传状态 |

仅具备 USB 接口的打印机需经本地打印控件（c-lodop）由 PC 中转。具备以太网或云打印能力的机型可取消该中间层。

### 8.2 选型对比

| | 网络直连 | 云打印 | USB + PC |
| --- | --- | --- | --- |
| 部署 | 配置 IP，同网段 | 配网即用，自动出网 | 安装驱动或控件 |
| 跨网络 / NAT | 否，需 VPN 或端口映射 | 支持 | 不支持 |
| 多仓统一管理 | 一般 | 最优 | 较弱 |
| 延迟 | 最低（毫秒级） | 略高（一次轮询或长连） | 低 |
| 数据是否出网 | 否 | 是，经厂商云 | 否 |
| 适用 | 单仓内网稳定 | 多仓、异地、无人值守 | 存量设备、PDF 渲染 |

公网直接端口映射不作推荐，应通过 VPN 或云平台打通。

选型建议：新采购机型带以太网接口，保留直连能力；多仓统一管理时叠加上云能力。USB 形态仅作存量兼容，不再新增。

### 8.3 标签尺寸

标签尺寸由介质与模板共同决定。以下三处必须对齐：

| 层 | 声明内容 | 维护方 |
| --- | --- | --- |
| 模板 | 宽 × 高、DPI、用途 | 系统（标签设计器） |
| 打印机 | 最大打印宽度、分辨率、当前装载介质 | 设备档案 |
| 实物纸 | 当前实际装载的纸卷 | 仓管换纸时登记 |

校验规则三条：

1. 模板宽度 ≤ 打印机最大打印宽度
2. 模板 DPI = 打印机 DPI，否则条码变形、无法识读
3. 更换尺寸须更换介质并重新校准间隙或黑标传感器

一台打印机同一时刻只装载一种介质。该约束为物理限制，系统记录「当前装载介质」，不假设单台设备可输出全部尺寸。

### 8.4 常用尺寸

| 用途 | 尺寸 | 介质 |
| --- | --- | --- |
| 快递面单 | 100 × 150 mm（4 × 6 in） | 热敏 |
| 大件 / 货运面单 | 100 × 100 mm | 热敏 |
| 库位 / 货架标签 | 60 × 40 mm、80 × 60 mm | 热转印 |
| 设备标签 | 40 × 30 mm | 热转印 |
| 价签 / 吊牌 | 40 × 30、50 × 30、70 × 20 mm | 热敏或热转印 |

### 8.5 介质类型

| | 热敏（Direct Thermal） | 热转印（Thermal Transfer） |
| --- | --- | --- |
| 碳带 | 不需要 | 需要 |
| 可读时长 | 约 6 个月褪色 | 3 至 5 年 |
| 成本 | 低 | 高（含碳带） |
| 适用 | 面单 | 库位标签、设备标签 |

面单一次性贴出，使用热敏；库位与设备标签需长期在架，使用热转印。同一台设备更换耗材可支持两种介质，设备档案记录当前介质类型。

### 8.6 打印场景

| | 打面单 | 打标签 |
| --- | --- | --- |
| 触发方式 | 订单发货，系统自动 | 建档、上架时人工触发 |
| 尺寸 | 固定 100 × 150 mm | 多种，随业务对象变化 |
| 介质 | 热敏 | 以热转印为主 |
| 发起方 | 系统 | 作业人员 |
| 失败后果 | 无法发货 | 库位无法识别 |

系统内设两个打印场景、两套模板。

## 九、设备生命周期

1. **接入**：公司机配置 Device Owner；自带机安装应用并首次登记；打印机配置 IP 或绑定 PC
2. **登记身份**：IMEI / UUID / 序列号 + IP
3. **绑定使用**：绑定人员与执行单元；打印机绑定工位与介质模板
4. **在线与故障**：心跳、探活、报修、换机
5. **退场**：解绑并退出资源池

跨仓流转走统一调拨单（DOC-SPC-003 设备类型），属于使用地点变更。

## 十二、原型现状

原型设备台账为只读列表，含统计卡、设备表、调拨列表三部分。第六章四个动作的交互尚未实现。设备类取七值（含 AGV、摄像头、称重机、扫码枪），与三类范围不一致。打印机在数据层为 USB 挂 PC 模型，无本机 IP 字段。
