# Proposal

## Why

3PL 仓储服务商需要一套多货主的管理系统。当前工作区没有任何业务代码，客户与商品两类主数据只能靠 Excel 与人工维护，既无法对货主开放，也无法支撑后续的仓库网络与执行端。

首期只做**客户管理 + 商品中心**两块业务，配齐登录、用户、角色、数据权限等平台底座，把货主端与仓网管理端两个前端跑起来。

仓库网络（空间树、库区、库位、货架模板）已完成设计但不在本期实施，见 `deferred/`。它依赖的现场资料采集成本高，且没有仓库时商品与货主仍然能独立成立——先跑通「货主 — 商品 — 审核 — 标签」这条最短链路，比先建仓库更快拿到可验证的结果。

## 调研依据

本变更的建模与选型依据以下调研文档，实现前须保持与其结论一致：

- `docs/research/wms-open-source-landscape.md`：开源 WMS 全景与许可排查，确立零商业授权前提。
- `docs/research/master-data-modeling.md`：多货主隔离、仓库空间建模、商品标识三个层次的对照分析。
- `docs/research/rbac-and-data-scope.md`：RBAC 与数据权限的五种候选对照。
- `docs/research/frontend-stack.md`：Web 与 PDA 的 UI 库选型。

## What Changes

- 新建**货主端**：登录、商品列表、商品建档、批量导入、SKUID 标签打印。
- 新建**仓网管理端**：客户管理（档案、联系人、税号、账号）、商品中心（品类、审核）、系统管理（用户、角色、字典、编码规则、审计）。
- 建立主数据模型：货主、联系人、税号、SKUID、条码、包装层级、品类、品牌。
- 建立平台能力：RBAC、货主维度数据权限、统一编码规则、数据字典、审计日志。
- 建立双端共用的设计令牌与前端基础包。
- **BREAKING**：无（新建项目，无存量代码与数据）。
- **上线方式**：首期货主端由 3PL 内部人员以货主账号操作，暂不向外部货主开放。数据隔离、审核流程与标签打印仍按真实多货主设计，确保二期开放时不需要改动。

**不做**：仓库网络与空间模型（含库区、巷道、货架、库位、货架模板、混放策略）、合同与货主合作仓、子账号、组织架构、双因素认证、通知推送、仓库平面图、单仓执行端、PDA、库存台账、出入库作业、计费结算。均已设计或部分设计，见 `deferred/` 与 `design.md` 的「后续演进」。

## Capabilities

### New Capabilities

- `platform-administration`: 登录与会话、密码策略、邮箱找回密码、用户与角色、权限点、货主维度数据权限、统一编码规则、数据字典、审计日志。
- `customer-management`: 货主档案、客户类型、状态流转、联系人、税号、主账号开通、负责客服、终止边界、货主端数据隔离。
- `product-center`: 品类、品牌、SKU 建档与审核、SKUID 编码、条码、包装层级、批量导入、SKUID 标签打印、启停状态。

### Deferred Capabilities

以下能力的规格与任务已完成，但不属于本变更的实施范围，文件保留在 `deferred/`：

- **warehouse-network**：仓库档案、租约、作业日历、服务能力、空间层级、库区用途、库位编码与容量、混放策略、货架模板、建仓向导。
- **组织架构**：公司 + 部门两级。
- **合同与合作仓**：货主与仓库的合作关系、合同附件、到期提醒。

## Impact

- **代码**：新增后端服务（Java 21 + Spring Boot 3，四个 Maven 模块）、两个前端工程（Vue 3 + Vite + TypeScript + Ant Design Vue 4）、`packages/tokens` 与 `packages/ui-web`。
- **数据**：新增 24 张表，分三组：平台 12、客户 4、商品 8。全部带软删除与审计四字段。
- **接口**：新增面向货主端与仓网端的两组 REST 接口；不含对外开放 API。
- **依赖**：PostgreSQL、Valkey、MinIO；不引入消息队列、搜索引擎与微服务组件。全部依赖满足零商业授权约束。
- **非功能基线**：按 30 万 SKUID 规划数据模型；界面文案预留中英双语；全部时间以 UTC 存储、按仓库时区展示。
- **外部系统**：本期不做入站对接，也不做通知推送。
