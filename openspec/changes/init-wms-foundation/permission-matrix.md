# 权限矩阵

首期六个角色 × 27 个权限点。

**这是参考模板，不是系统预置，也不是规格要求。**

系统只提供两个机制：权限点（功能粒度）与货主维度的数据范围（全部 / 指定货主）。角色是客户自己建的组合，数量与命名由组织结构决定。

仓库网络后置后，「仓管主管」「仓管员」两个角色随之去掉——它们的功能权限全部落在空间模型上，本期没有对象可管。

## 一、角色

| 简称 | 角色 | 端 | 职责 |
| --- | --- | :-: | --- |
| 超管 | 超级管理员 | 后台 | 全部权限，唯一预置，功能权限自动全量 |
| 总监 | 运营总监 | 后台 | 看全部货主，管合作与账号开通 |
| 客服主管 | 客服主管 | 后台 | 看全部货主，带客服团队 |
| 客服 | 客服专员 | 后台 | 只看自己负责的货主 |
| 审核 | 商品审核员 | 后台 | 只审商品，不碰其他 |
| 货主 | 货主主账号 | 货主端 | 管自己的商品与标签 |

权限点命名遵循 `模块:实体:动作`，与 `sys_menu.perms` 一致。

## 五、数据范围默认值

只有一个维度：货主。取值两档：`全部` / `指定货主`。

| 角色 | 货主范围 |
| --- | --- |
| 超管 | 全部（且不受限） |
| 总监 | 全部 |
| 客服主管 | 全部 |
| 客服 | 指定：自己担任主或副负责人的货主 |
| 审核 | 全部 |
| 货主 | 强制本货主，不计入可配置范围 |

「自己负责的货主」按货主负责人的主副关系计算，主与副都计入。

客服需要看更多货主时，不新建角色，直接在该用户上把货主范围改成「全部」——这正是「角色默认 + 用户可覆盖」的用途。

## 六、两条约束

**① 新权限点默认不授予任何角色**

新功能上线后，除超级管理员外所有角色都看不到，必须显式授权。

**② 超级管理员功能权限自动全量，数据范围不受限**

不走业务代码特判，靠角色本身带全量标记，新增权限点自动包含。
