# Proposal

## Why

3PL 仓储服务商需要一套多货主、多仓型、境内外统一的管理系统。当前工作区没有任何业务代码，客户、仓库、商品三类主数据只能靠 Excel 与人工维护，既无法对货主开放，也无法支撑后续自建的「单仓执行端」与「PDA」。

主数据是所有作业的上游：库位树决定了上架与拣货能不能落位，SKUID 决定了库存能不能分账，货主维度决定了数据隔离是不是模型层解决的问题。这三样如果在执行端上线后再补，等于把已有作业数据全部回填，成本不可控。因此首期先把主数据基座立起来，作业端后置。

## What Changes

- 新建**货主端**：登录、子账号开通、商品管理（含批量导入与 SKUID 标签打印）。
- 新建**仓网管理端**：客户管理、仓库网络（含空间层级与库位）、商品中心（含审核）、系统管理。
- 建立主数据模型：货主、仓库、仓库能力、空间节点、运输资源、SKUID、条码、包装层级、品类。
- 建立平台能力：RBAC 与「仓库 + 货主 + 库区」三维数据权限、TOTP 双因素、统一编码规则、审计日志、中英双语预留。
- 建立双端共用的设计令牌与前端基础包。
- **BREAKING**：无（新建项目，无存量代码与数据）。

**不做**：单仓执行端、PDA、库存台账、出入库作业、计费结算、订单路由、海外仓头程与清关、库位地图可视化。这些能力在后续独立变更中新增，其中库位地图所需的前置字段已在 `design.md` 的「后续演进」中列明。

## Capabilities

### New Capabilities

- `platform-administration`: 登录与会话、双因素认证、用户与角色、三维数据权限、统一编码规则、数据字典、审计日志。
- `customer-management`: 货主（客户）档案、合同附件、货主主账号开通、子账号与角色分配、客户类型标签。
- `warehouse-network`: 仓库档案、仓库服务能力、空间层级（园区/栋/层/区/巷道/货架/层/库位）、虚拟库位、运输资源、库位批量导入。
- `product-center`: 品类与品牌、SKU 建档与审核、SKUID 编码规则、条码、包装层级、批量导入、SKUID 标签打印与审计。

### Modified Capabilities

无。当前 `openspec/specs/` 为空，本变更为初始基线。

## Impact

- **代码**：新增后端服务（Java 17 + Spring Boot 3，模块化单体）、两个前端工程（Vue 3 + Vite + Element Plus）、`packages/tokens` 设计令牌包。
- **数据**：新增 25 张主数据与平台表，全部带软删除与审计四字段；业务表带 `owner_id` 与 `warehouse_id`。
- **接口**：新增面向货主端与仓网端的两组 REST 接口；不含对外开放 API。
- **依赖**：MySQL 8.0、Redis 7、MinIO；不引入消息队列、搜索引擎与微服务组件。
- **非功能基线**：按单仓日均 1 万单、30 万 SKUID、单仓 2 万有库存 SKU 规划数据模型；界面文案预留中英双语；全部时间以 UTC 存储、按仓库时区展示。
- **外部系统**：本变更不与任何外部系统对接。
