# 测试用例

**来源**：`openspec/specs/` 的每个 Scenario 对应一条用例，不另起事实来源。

**编号**：`TC-PA-*` 平台管理，`TC-CM-*` 客户管理。编号一经分配不复用——删掉的用例保留编号并标「已废弃」。

**状态取值**：

| 状态 | 含义 |
| --- | --- |
| 自动 | 有单测断言覆盖，`mvn verify` 即可验证 |
| 自动+手工 | 单测覆盖逻辑，端到端行为另经手工验证（手工步骤见「验证方式」列） |
| 部分 | 只实现了一部分，缺口在「验证方式」列注明 |
| 未实现 | 对应任务尚未开始 |
| 不适用 | 结构上不可能发生，保留用例以记录判断 |

**维护**：每完成一条任务，更新对应行的状态与验证方式。归档时本文件随 change 进入 `archive/`。

```bash
# 依赖服务（PG 映射到 15432，避开本机已占用的 5432）
cd code/backend

# 应用
DB_URL="jdbc:postgresql://127.0.0.1:15432/yunwms" \

```

### 准备测试账号

`sys_user.password_hash` 存 BCrypt（`$2a$` / `$2y$` 均可）。本机没有 bcrypt 工具时可用 `htpasswd`：

```bash
HASH=$(htpasswd -bnBC 10 "" 'Admin@1234' | tr -d ':\n')

docker exec yunwms-postgres psql -U yunwms -d yunwms -c "
INSERT INTO sys_user(login_name,display_name,subject_type,password_hash,email,status,must_change_password)
VALUES('probe.staff','探针员工','STAFF','$HASH','probe@example.com','ACTIVE',false);"
```

> **员工必须有 email**（`ck_user_email_required`）。货主账号可以没有。
> 需要「待改密」账号时把 `must_change_password` 改为 `true`。

### TC-PA-001 / 002 / 004 登录

```bash
# 001 员工登录：期望 code=0，data 含 token、subjectType=STAFF、accessiblePortals=["console"]
curl -s -X POST localhost:8080/api/auth/login -H 'Content-Type: application/json' \
  -d '{"loginName":"probe.staff","password":"Admin@1234"}'

# 002 货主登录：期望 subjectType=OWNER、ownerId 为**字符串**、accessiblePortals=["portal"]

# 004 停用主体：期望 code=40102、message=账号已停用
#     psql -c "UPDATE sys_user SET status='DISABLED' WHERE login_name='probe.staff'"

# 对照项：密码错误与账号不存在必须逐字相同（否则可被用来枚举账号）
curl -s -X POST localhost:8080/api/auth/login -H 'Content-Type: application/json' \
  -d '{"loginName":"probe.staff","password":"wrong"}'
curl -s -X POST localhost:8080/api/auth/login -H 'Content-Type: application/json' \
  -d '{"loginName":"nobody","password":"wrong"}'
# 两条均应为 {"code":40101,"message":"登录名或密码不正确","data":null}
```

### TC-PA-006 首次登录强制改密

```bash
# 1. 登录拿 token（must_change_password=true 的账号）
#    期望 code=0 且 data.mustChangePassword=true

# 2. 用该 token 访问任意业务路径：期望 HTTP 401 + code=40104
curl -s -w '\n[http=%{http_code}]\n' -H "Authorization: Bearer $TOKEN" localhost:8080/api/anything

# 3. 改密成功后，同一 token 再访问：期望 404（说明已放行到 DispatcherServlet）
curl -s -o /dev/null -w '%{http_code}\n' -H "Authorization: Bearer $TOKEN" localhost:8080/api/anything
```

> `40104` 与 `40100` 必须分开：待改密用户是**已登录**的，回「未登录」会让前端跳登录页，
> 形成「登录 → 被踢回登录」的循环。前端拦截器须先判 `code=40104` 再判 HTTP 401。

### TC-PA-007 连续错误锁定

```bash
# 连错 5 次
for i in 1 2 3 4 5; do
  curl -s -X POST localhost:8080/api/auth/login -H 'Content-Type: application/json' \
    -d '{"loginName":"probe.staff","password":"wrong"}'
done

# 第 6 次用**正确**密码：期望 code=40103（锁定期内即使密码正确也拒绝）
curl -s -X POST localhost:8080/api/auth/login -H 'Content-Type: application/json' \
  -d '{"loginName":"probe.staff","password":"Admin@1234"}'

# 库内核对
docker exec yunwms-postgres psql -U yunwms -d yunwms -c \
  "select failed_attempts, locked_until > now() as 已锁 from sys_user where login_name='probe.staff';"

# 窗口边界：把 last_failed_at 改到 31 分钟前，再错一次 → failed_attempts 应为 1（不是 6）
docker exec yunwms-postgres psql -U yunwms -d yunwms -c \
  "UPDATE sys_user SET failed_attempts=3, last_failed_at=now()-interval '31 minutes' WHERE login_name='probe.staff';"
```

## 集成测试现状

已引入 `@SpringBootTest` + Testcontainers（`BootstrapIntegrationTest`），三条用例覆盖迁移、初始账号登录、40104 拦截。

**仍未覆盖**：`FOR UPDATE` 并发计数、30 分钟窗口边界、令牌到期、会话失效。这些仍需手工验证，或留待后续轮次补测。

手工脚本不删——排障时仍要用。原计划是它被完全替代，实际是逐步替代：

1. **不可复现**——结论只存在于执行者的终端里，换人换环境要重跑
2. **覆盖不到 SQL**——单测把 Mapper 整个 mock 掉，`FOR UPDATE`、窗口判定、并发计数都验不了
3. **迁移无人验证**——`V022` 加列之后，没有任何自动测试确认空库能跑通 21 份迁移

集成测试落地后，本节的「自动+手工」应逐步降级为「自动」，手工脚本只保留排障用途。
