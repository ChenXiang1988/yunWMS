# Proposal

## Why

`init-wms-foundation` 已交付规格、设计决策、权限矩阵与界面结构，并完成工程骨架。规格描述的是「系统应该怎样」，但没有一行业务代码实现它。

本变更实现其中的**平台底座与客户管理**：登录、会话、用户、角色、数据权限、货主档案、联系人、税号、账号，以及对应的两端页面。

商品中心由 `implement-sku` 实现，本变更不涉及。

## 调研依据

规格阶段的三份调研仍是本变更的实现依据，实现与其中结论冲突时须先回到规格讨论：

- `docs/research/rbac-and-data-scope.md`：RBAC 与数据权限的候选对照，本变更按其结论实现角色与货主维度范围。
- `docs/research/auth-middleware.md`：认证选型为 Sa-Token，已在工程骨架阶段落地。
- `docs/research/master-data-modeling.md`：货主隔离与主数据建模。

## What Changes

- 实现**认证与会话**：双主体登录、令牌签发、密码策略与失败锁定、首次登录强制改密、会话失效与踢人、邮箱找回密码。
- 实现**权限与治理**：用户管理、角色与三类功能权限、货主维度数据范围（两层配置）、货主账号强制过滤、编码规则引擎、数据字典、审计日志。
- 实现**客户管理**：货主档案增改查、四态状态机、主账号开通、客户类型、联系人与负责客服（多对一主一副）、税号。
- 实现**两端相关页面**：货主端登录与改密、仓网端客户管理、仓网端系统管理、菜单驱动的动态路由与按钮权限。
- **BREAKING**：无。全部为新建代码。
- **上线方式**：与 `init-wms-foundation` 的边界一致，首期货主端由 3PL 内部人员以货主账号操作。

**行为依据**：本变更不引入新的系统行为，全部按 `init-wms-foundation` 归档后生效的规格实现（见 `openspec/specs/`）。实现中发现规格不可行时，**MUST** 先回到规格讨论并单独开 change，**MUST NOT** 在本变更内改行为。

## Impact

- **代码**：`code/backend` 的 `wms-auth`、`wms-master`、`wms-web`、`wms-app` 四个模块；`code/frontend` 的两个应用。
- **数据**：使用已建的 24 张表中的平台 12 张与客户 4 张，**不新增表**。

  实现中发现一处模型缺陷并已修：`sys_user` 缺「最近一次密码失败时间」，导致 1.2 的锁定只能按「连续失败」计数，无法表达规格要求的 30 分钟滑动窗口。已由 `778b8d2` 新增迁移 `V022__sys_user_last_failed_at.sql`（`ALTER TABLE sys_user ADD COLUMN last_failed_at timestamptz`），迁移与代码分两次提交。

  其余表结构变更仍需按 `AGENTS.md` 的数据库变更顺序另开迁移。
- **接口**：新增认证、用户、角色、权限、数据范围、货主、联系人、税号、字典、编码规则、审计共 11 组接口。
- **非目标**：商品与品类相关的一切；仓库与空间模型；通知推送；组织架构。
