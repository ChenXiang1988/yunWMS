| 1 | 规格与建模不符 | `platform-administration` 写「预置客户类型、品类、温区、合规属性等字典」，但品类是独立表 `category`（V010，两级树 + 必填项模板），不是「类型 + 项」。**未预置 `CATEGORY` 字典**，否则会与 `category` 形成第二真源。规格该句需修正 |
| 2 | 字典项的 `value` 是本批首次定义 | `OWNER_TYPE` = `BRAND`/`FORWARDER`，`TEMP_ZONE` = `NORMAL`/`CHILLED`/`FROZEN`/`CONSTANT`，`COMPLIANCE` = `GENERAL`/`BATTERY`/`LIQUID`/`POWDER`/`MAGNETIC`/`DANGEROUS`。3.1 / 3.4 与商品模块 **MUST** 沿用，否则会出现「字典里有、代码里另一个值」 |
| 3 | 字典暂落 `wms-auth` | 与用户/角色同属平台管理域，未新建 `wms-platform` 模块。若后续拆模块，这部分类需整体搬迁 |

### 3.1 已裁决

| # | 事项 | 结论 |
|---|---|---|
| 1 | SKU 前缀何时确定 | **建档即确定、即占用、即锁定**，草稿也不可改。`ux_owner_sku_prefix` 全表唯一索引不改。依据：`V001` 列注释、`ui-structure` 第 211 行、`product-center` 规格、`design.md` 第 556 行，四处一致；`customer-management` 原写「草稿可改」是唯一的例外，已修正 4 处 |
| 2 | 邮政编码必填性 | **按地区豁免**。`PROVINCE` 字典项的 `ext` 加 `postalCodeRequired: false`，大陆各省不写该键（默认必填），港澳台写 `false`。原因是港澳台无邮编但同属中国，按「国家」豁免不够细 |
| 3 | 建档入口 | **两条都要**：「保存草稿」（落 DRAFT）与「直接提交」（落合作中）。依据是货主档案场景「创建货主 → 状态为合作中」与状态流转「草稿可提交」，两者并存说明有两条入口 |
